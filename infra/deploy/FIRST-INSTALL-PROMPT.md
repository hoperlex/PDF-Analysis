# First installation: instructions for a simple AI agent

You install the AuditManager stack on THIS server with one script, `infra/deploy/first-install.sh`. You do not need to
understand it. Follow what it prints, literally. The owner gives you the values written in angle brackets.

## The command

Run it as root, from the root of the repository clone, with only the options the owner named:

    sudo infra/deploy/first-install.sh --email <owner's e-mail> [--domain <public DNS name>] [--norms-bundle <bundle directory>]

It takes from fifteen minutes to over an hour (image build, norms import). If your tool times out or the command is cut off,
run the same command again: it continues where it stopped. Everything it prints is also in
`/var/log/<instance>-first-install.log` (the instance is `auditmanager` unless the owner named another); read the end of it with
`tail -n 30`. It contains no secret.

## What the last line means

1. `DONE: ...` is success. Tell the owner that line and the block "for the owner" above it (the GitHub values and the
   paths of two private files). Then stop.
2. `STOP [code]: <action>` is one thing to do. Do exactly the action as printed, then run the same command again, unchanged.
   If the action starts with `ASK THE OWNER`, do not act: tell the owner the whole STOP line, wait for the answer, and
   run the command again only when the owner says so (with a different option only if the owner names it).
3. Anything else (no STOP and no DONE, a Python traceback, `command not found`): stop and show the owner the last 30 lines.
4. The same STOP code three times in a row: stop and show the owner the last 30 lines. The one exception is `already_running`:
   an earlier command is still working, so only wait and look at the log, as that STOP line says.

## Never

- Never read, print, copy or repeat a file that holds a password or a key: `/root/<instance>-admin-password.txt`,
  `/root/<instance>-deploy-key` (its `.pub` is public), `infra/deploy/env/alpha.env`, `infra/deploy/env/provider.env`. Tell the
  owner their paths; the owner reads them.
- Never edit, delete, clean or reset anything in the clone (`git clean`, `git reset`, `git checkout`, `git stash`, `rm`), and
  never run `git pull` unless a STOP line tells you to.
- Never kill a process by name or pattern (`pkill`, `killall`), never stop a container, never remove a Docker volume or
  image, never run `docker compose` or `reset.sh` yourself unless a STOP line prints the exact command.
- Never push to `origin`, never touch `main`, never create a tag or a branch.
- Never add `--skip-executors`, `--resume-stage` or `--set` on your own; they are the owner's decisions.
- Never paste a password, token, key or the content of any `.env` file into a message.

## The STOP codes

Each row is the action printed after the code (`<...>` stands for the facts of this run). A line that begins `ASK THE OWNER`
is for the owner. This table is generated by `infra/deploy/first-install.sh --print-codes --markdown`, and a test holds it equal
to the script's own table.
