# First installation: instructions for a simple AI agent

You install the AuditManager stack on THIS server with one script, `infra/deploy/first-install.sh`. You do not need to
understand it. Follow what it prints, literally. The owner gives you the values written in angle brackets.

## The command

Run it as root, **from the clone you were started in** (the owner's working copy), with only the options the owner named:

    sudo infra/deploy/first-install.sh --email <owner's e-mail> [--domain <public DNS name>] [--norms-bundle <bundle directory>]

Add `--norms-bundle` only when the owner gives you a directory. When the repository publishes the norms bundle
(`infra/norms/bundle-release.lock` is in it), the script downloads it from the GitHub release and imports it by itself, with no
option: that is several GB and takes a while, and a run that is cut off resumes the download. Pushes to `main` of the fork are
deployed by a timer on this server within five minutes (the default, `--deploy-mode local`; nothing is needed in GitHub). Add
`--deploy-mode github` only when the owner names it: GitHub Actions deploys then, and the script makes a deploy key.

The script makes the server's own checkout, `/srv/<instance>` (the instance is `auditmanager` unless the owner named another), from
this clone's origin, and continues in it by itself. You never work in `/srv/<instance>`, and the clone you started in is never
changed. If the norms were not imported (the owner block says so), run the same command again when the owner says they are available.

It takes from fifteen minutes to over an hour (image build, norms import). If your tool times out or the command is cut off, run
the same command again: it continues where it stopped. Everything it prints is also in `/var/log/<instance>-first-install.log`;
read the end of it with `tail -n 30`. It contains no secret.

## What the last line means

1. `DONE: ...` is success. Tell the owner that line and the block "for the owner" above it (how deploys happen; in github mode
   also the GitHub values to set; and the paths of the private files).
   Then stop. If this repository is a fork, add that its next work is listed in `docs/program/FORK_ROADMAP.md`.
2. `STOP [code]: <action>` is one thing to do. Do exactly the action as printed, then run the same command again, unchanged.
   Almost every action is a command or "wait and run again": do it yourself, do not ask.
3. A STOP line that begins `ASK THE OWNER` needs a fact only the owner holds: an e-mail address, the domain, a record at the
   registrar, a sign-in to a subscription, access to the repository, the provider's firewall, a password he set, or money. Tell
   the owner the whole line, wait for his answer, and run the command again only when he says so. Those are the only lines you
   ask about.
4. A STOP line that begins `REPORT TO THE OWNER` is a failure with nothing safe to try. Show the owner the whole line and the last
   30 lines of output, and stop. Do not retry.
5. Anything else (no STOP and no DONE, a Python traceback, `command not found`): stop and show the owner the last 30 lines.
6. The same STOP code three times in a row: stop and show the owner the last 30 lines. The one exception is `already_running`:
   an earlier command is still working, so only wait and look at the log, as that STOP line says.

## Never

- Never read, print, copy or repeat a file that holds a password or a key: `/root/<instance>-admin-password.txt`,
  `/root/<instance>-deploy-key` (its `.pub` is public), `infra/deploy/env/alpha.env`, `infra/deploy/env/provider.env`. Tell the
  owner their paths; the owner reads them.
- Never edit, delete, clean or reset anything in a clone (`git clean`, `git reset`, `git checkout`, `git stash`, `rm`), except
  by a command a STOP line prints.
- Never kill a process by name or pattern (`pkill`, `killall`), never stop a container, never remove a Docker volume or
  image, never run `docker compose` or `reset.sh` yourself unless a STOP line prints the exact command.
- Never push to `origin`, never touch `main`, never create a tag or a branch.
- Never add `--skip-executors`, `--resume-stage`, `--deploy-path`, `--deploy-mode` or `--set` on your own, except where a STOP line prints the
  exact command; they are the owner's decisions.
- Never paste a password, token, key or the content of any `.env` file into a message.
