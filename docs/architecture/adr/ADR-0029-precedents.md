# ADR-0029: Precedents — a model-free core that serves the AI critic through the client and the expert in «Разбор»

- Status: accepted
- Date: 2026-11-10; revised 2026-11-18 (ADR-OPTIMISE-01)
- Basis: the owner's direct polls of 2026-11-10 (`R-153q`…`R-153ar`; wording in `docs/program/OWNER_RULINGS_2026-09-17.md` section 3.55); the product decisions are the owner's, the engineering choices inside them the planner's. Two decisions are **temporary** with end conditions («Temporary decisions»). Decision 14 corrects the ADR after the AR v3 removal and the plan v2 critic (`R-154a`…`R-154h`). Revisable by a dated addendum.; amendment `R-156o`
- Amends: `ADR-0027` decisions 2, 3 and 6 and `DECISION-MEMORY-01` (Q4, Q8, Q9, Q10, section 5.3, phase M4), by dated notes there.
- Related: `ADR-0027`, `ADR-0028`, `ADR-0020`, `ADR-0021`, `ADR-0024`, `ADR-0026`. Lane task files (`docs/program/tasks/`) cite «ADR-0029 decision n».

## Context

Expert decisions kept in the decision memory (`ADR-0027`) must work for the product (`R-153x`, `R-153r`): the AI critic gets the norm reference and, later, similar cases; the expert sees in «Разбор» a neutral mark, a collapsed «Рекомендовано снять» queue, other experts' comments and «Возможные нормы». Forces: the memory holds no vectors; only a run under the stage layout has a frozen `stage_plan` (`ADR-0028` decision 5); the executor client receives only what its task holds; the production host has 4 GB (`R-146ad`) and the norm-corpus encoder peaks at 3 177,9 MiB (`docs/program/NORM_EMBEDDING_BAKEOFF.md`). The owner took no measurement before building (`R-153an`); see «Accepted risks».

## Decision

Open: the two temporary decisions («Temporary decisions») end only on their stated conditions; decision 11 is the second seal's work (sealed, decision 12); the last bullet of decision 14 (the veto applied to the plan v2 critic) is contradicted by `src/auditmanager/precedents/run_pass/critic_input.py` (it never vetoes) and waits for the owner's decision.

1. **One model-free core, a new bounded context `precedents`.** It imports only the `public` module of other contexts and never calls a model. It alone decides who votes, which mark a finding gets and which hint it shows; both consumers read it.
2. **Two consumers, one writer of verdicts.** The AI critic reads reference material through the executor client (decision 3); the expert reads marks, the queue, comments and «Возможные нормы» (`R-153x`). The ledger is written only by the expert: a mark is advice, the expert's ✓/✕ decides, and «Отмена» is a mark and a collapsed queue, never an automatic withdrawal (`R-153r`).
3. **Prompts stay static; the client brings the data.** The stand answers a task's `context_request` (kind `similar_cases` or `patterns`); the client appends one block after the JSON of `user_text`, headed `=== СПРАВОЧНО (не основание) ===`, echoes its digest in the answer and inserts nothing before the task text. A context failure never fails the task: on a refusal, a timeout or a 5xx the client calls the model without the block and says so in one line; the `Retry-After` rule of the runner API does not apply to context. The CLI tools stay closed; MCP is a later experiment (`R-153y`). The consent freezes an `executor_context_policy` like `norm_paragraph_context_policy`, only while the «контекст критику» switch is on (`R-153v`): kinds, scope, budget (two requests and 12 000 characters per task, a retry costs nothing) and method. The prompt paragraph explaining the block is added only to runs with a `stage_plan`; it changes `rules_sha256` of every v3 run (ship with an empty v3 queue or a consent note).
4. **Who votes, and the similarity that counts.** Corpus: cases of the **same section**, active at the moment of reading (a withdraw or a forget acts at once), the same `data_class`, verdict ✓ or ✕, within 24 months; a case without a section does not vote. **One vote per case**, its latest verdict; a comment never changes a vote; a `carried` decision does not vote on its own; an imported one votes as «without a shown mark». A case from the finding's own run does not vote; from one version of a document at most two votes (the most similar; ties by the smaller `case_id`). A vote is independent only if, at the decision, no refusal mark was in force on that finding and no «история документа» fact was shown; «in force» is what the server issued for that finding then, recorded by capture in `decision_memory_decision`; what the expert actually saw is not proved. Similarity: only profile `bge-m3-dense-v1`; cosine ≥ 0,85 is «аналогичное» and votes, ≥ 0,75 is «похожее» and serves comments, ≥ 0,92 within one document is the history fact; the figures are starting values that the replay (decision 6) adjusts. Search is an exact scan inside the section; no vector means «Недоступно», no fallback (`R-153ac`). The encoder input is the view `finding_v1` (category, finding text, head of the recommendation; at most 1 000 characters, so that it stays under the encoder's 512-token limit; a cut is marked).
   - **On the fork server** (`R-156c`, `R-156j`, `R-156l`) the similarity profile is the active embedding profile of `ADR-0020` decision 7; the figures above belong to `bge-m3-dense-v1` and are re-tuned by the replay (decision 6) on the new profile before any section's marks are switched on. The current production VPS is unchanged.
     Amendment 2026-11-18 (`R-156o`): for the beta the fork keeps `bge-m3-dense-v1`, so the figures 0.85 / 0.75 / 0.92 apply there unchanged; the replay re-tunes them only when the profile changes after the beta. Section marks stay off by default until the replay report of decision 6 allows them.
5. **Marks, «снять» and their protections.** Marks: `often_rejected` (≥ 5 votes, ≥ 80 % refusals), `likely_accepted` (the same for acceptance), `mixed` (≥ 5 votes, both verdicts, neither share ≥ 80 %), `few`/`none` (no mark); unanimous refusals never give `mixed`. **`cancel_suggested` is part of `often_rejected`** and needs all of: ≥ 5 independent votes (`R-153ad`), ≥ 90 % refusals, the latest vote a refusal, votes from ≥ 2 projects, **a critic reviewed the finding (AI in plan v3, deterministic in plan v2) and did not veto** (`R-153ar`), and no stop-word of the owner in the finding text or recommendation (`R-153ae`); stop-words are an administrator's list matched by word stems, and a match hides «снять». The core takes «critic in plan» and «reviewed» as inputs; mapping a plan's critic output to them is the pass's work (`PREC-PASS`). **Reviewed**: a linked candidate carries a critic record; **veto**: any linked candidate got `accept` or `needs_human`. A text finding is linked to the candidates whose sources include its `primary_text_<key>`, a candidate finding through `extended_observation_ref`. Each candidate stores `context_kinds`, the reference kinds the critic saw, so a veto is not an echo of the same neighbours. A finding outside the AI critic's window (≤ 40 records and 16 000 characters; the rest is marked `outside_critic_window`), or that no critic reviewed, gets only the line «Прецедентов: N (критик не разбирал)» and never enters the queue. **Hints** (≤ 2 per finding, no model text): P1 the reason for refusals (a refusing vote's comment, later an approved pattern), only under `often_rejected` or `cancel_suggested`; P4 the critic disagrees (exactly one linked candidate whose advice contradicts the mark); P5 document history (a vote from an earlier version of the same document at cosine ≥ 0,92; a neutral fact, and a shown refusal ends that vote's independence).
6. **Switching on is by section, from a replay report; every switch is off by default.** The replay tool (`CRIT-REPLAY-01`) is a product tool, not a measurement: it cuts the history by time (70 % early to tune, 30 % late to check), leaves decisions made under a shown refusal mark out of the «снять» check, and reports the base refusal rate, the gain, the precision of «снять» and the harm (accepted findings it would have hidden). A section may show refusal marks when precision ≥ 0,90 on ≥ 30 cases, the gain ≥ 0,15, the harm ≤ 2 % and zero on protected findings (`R-153ah`); the administrator turns it on from the report, and the journal row carries its digest. Neutral marks show at once. Three switches, journalled (`precedent_setting_event`), are all off: «один список», «контекст критику», marks per section. A run's publication mode is frozen by a marker at its start, so a switch acts on new runs only.
7. **«Один список»: the extended-review candidates become findings in «Разбор» (`R-153al`).** A new publisher turns a group of N observations into one finding, whose canonical observation is the first member; categories `drawing_discrepancy` and `cross_source` are added (a mixed group is `cross_source`); a group wholly of `primary_text_*` is not published twice. **Gate v2:** a block as evidence is accepted when its `blk_` is in this run's geometry, the crop's sha matches `page_crops` and a quote, if present, is verbatim in that block's recognised text. **Block grounding proves a place, not a content:** for block evidence the text gate's refusal `quote_in_recognised_text` is cancelled; for text evidence the rule is unchanged. Memory capture moves to `dm-capture/2` in the same release, because capture skips empty evidence. The legacy run is unchanged: text findings only (temporary decision 1). The number of findings will grow; the queue and the critic's advice are the help.
8. **Vectors: exact scan, an offline encoder in a night window, one pause (`R-153w`, `R-153ab`, `R-153ap`).** No HNSW. The encoder is a container of the norms-worker image run as `embed-texts`: **no database and no network**, a hard `mem_limit` that compose refuses to start without, an equal swap limit, a maximum `oom_score_adj`, two CPUs and two threads; it reads a file of intents (deduplicated by `input_sha256`) and writes vectors, which the worker imports with a unit-norm check; a text over 512 tokens is `poisoned` and visible to the administrator. **The window** is by default 01:00–06:00, the time zone a setting: at its start the stand stops issuing new runs as the analysis pause does and waits for running attempts; if they do not end before the window does, it is **loudly skipped** with a reason. The model is unloaded after the container exits; a run started at night waits for the morning with a note. **One «Пауза» button** in the top strip with two items, «Выдача анализа» and «Векторы»; the badge «Векторы на паузе» exists only during a pause, and on a pause no window starts.
   - **On the fork server** (`R-156b`, `R-156c`, `R-156l`), once implemented there (`R-156k`), the resident embedder of `ADR-0020` decision 7 encodes at capture and probe time: no night window, timer, exchange volume or «until the move» text, and neither the norms-worker image nor the temporary `norm-embed` on the stand. The «Векторы» pause, the exact scan inside a section and the unit-norm check stay. The current production VPS is unchanged.
9. **Norms for the critic (`R-153aa`).** Paragraph text already reaches the critic in `norm_context`. The PNG crop of a norm page is declared among the task's `images` when the task is created, only from this run's norm-context paragraphs, only for a cell whose model accepts images, at most 2 per task (a Claude Code host takes none); it is rendered once from a one-page PDF and kept (`norm_crop_render`). «Возможные нормы» in the finding card come from the same paragraphs and do not depend on the encoder.
10. **Comments have their own table (`R-153ag`).** `decision_memory_comment` keeps the experts' comments as memory content (KEEP); on a case's first ✓/✕ the earlier comments are carried into it; the forget protection refuses an insert into a forgotten case. This revises `DECISION-MEMORY-01` Q8.
11. **The second seal (patterns, quality, cross-document).** **Failure patterns (`R-153ai`):** the algorithm proposes, an expert approves; an unapproved pattern never reaches P1; a pattern whose group dissolves is suspended. **Cross-document parameters (`R-153aj`):** a discrepancy is a finding of the **newer** document's run with the other document's evidence; there is no project-level finding; different units are not compared. **Quality of stages and models (`R-153ak`):** the share of accepted findings by `stage_plan` cell and section, the model read from the cell (`model_identity` is not copied into the memory).
12. **Seals.** The first seal is one contract and one migration for everything above that needs them: **1.51.0 / `0064`** (`CRIT-SEAL-50`); the AR v3 removal wave took 1.50.0 / `0063` first (`R-154h`). The second seal (patterns, cross-document evidence, parameter facts, `parameter_mismatch`) was sealed as **1.54.0 / `0067`** (`CRIT-SEAL-53`; `CRIT-SEAL-51` in the task files), after the debt seal 1.52.0 / `0065` (`CRIT-SEAL-52`) and `RUN-DELETE-01` 1.53.0 / `0066` (the contract README calls 1.52.0 the programme's second seal; here «second seal» means the content of decision 11). Every additive change is a minor version (`docs/program/VERSIONING_AND_FREEZE_POLICY.md`). Every new table, command type and event type is classified in the recovery tools by the lane that adds it; new events use the prefixes `precedent.` and `vector.`.
13. **Amendments to `ADR-0027` and `DECISION-MEMORY-01`.** `ADR-0027` decisions 2, 3 and 6 are refined as `ADR-0027` records. In `DECISION-MEMORY-01`: Q4 is closed by `R-153z`; Q8 is revised by decision 10; Q9(b) and Q10 are answered in part; section 5.3 and phase M4 are replaced by this ADR.
14. **Correction after the AR v3 removal and the plan v2 critic (`R-154a`…`R-154h`).**
    - AR v3 is removed (`R-154a`); the rules that applied only to it are not built: hints P2 (importance) and P3 (norm) and the ban on «снять» for `critical` and normative AR v3 findings.
    - The extended-review plan v3 is opt-in by `AUDITMANAGER_EXTENDED_ANALYSIS_PLAN=v3`, **default v2** (`R-154b`; `EXTENDED_PLAN_DEFAULT` in `src/auditmanager/runs/preflight.py`).
    - Plan v2 is the original's legacy flow with the executors split per stage (`R-154e`); it has the original's **deterministic critic and corrector**, without a model, after the norms, advice only (`R-154f`), and its «Критик» and «Уточнение» rows and counters show real results (`R-154g`): `docs/program/V2-ORIGINAL-REVIEW-01.md`.
    - **So «В3» applies to v2 and v3 in the same way:** a finding that a critic reviewed and did not veto can get «снять»; a finding no critic reviewed cannot (`R-153ar`). The pass maps the v2 critic's output (`src/auditmanager/precedents/run_pass/critic_input.py`): a v2 run with the marker `original_review: deterministic-v1` has the deterministic critic in plan, and its finding counts as reviewed when a linked candidate carries that critic's record (decision 5); a v2 run without the marker has no critic in plan, and its findings get no «снять».
    - Neutral marks, comments and «Возможные нормы» work under any plan; the critic's reference block (decision 3) works only under v3, because only the AI critic reads it.
    - The veto of `R-153ae` is applied to the deterministic critic of plan v2 in the same way. The owner did not rule on that case separately: this is the planner's extension, revisable.

## Temporary decisions

Each has an end condition; neither may be taken as the final shape without a new owner decision.

1. **The legacy run stays as the legacy (plan label «В1»).** A run without a `stage_plan` gets no «один список» and no reference block for the critic; it works as in the legacy original (`R-153y`). It is the rollback path: the layout switch (`ADR-0028` decision 14) takes a run back to the legacy route, and the marker `publication_mode = text_only` makes it read as before. **Ends when** the layout switch is removed (`ADR-0028` decision 14) or the owner decides otherwise.
2. **The encoder runs only at night, on our own server (plan label «В2»).**
   - While the production server has 4 GB and no measurement, the encoder is the offline container of decision 8 inside the night window, with no new runs started during it (`R-153ap`).
   - Consequences: the AI critic (plan v3) gets the norm reference only and the line `Прецеденты: недоступно до переезда (временный ночной режим).` (`R-153aq`); the stand answers a context request for similar cases with `unavailable`, reason `until_move`; the expert sees precedents the next morning, with one short line above the list saying what is available after the move and what works in the night window and how (`R-153am`).
   - **Ends when any one of these holds:**
     - the database and object storage move to Yandex and the encoder runs on a separate machine (`R-153ab`; plan `docs/program/YC-MOVE-PLAN.md`);
     - a compressed model with a **proven vector compatibility** is built in a future task and the owner permits it;
     - the server is enlarged.
   - When it ends, the three lines of text that mention the night mode are removed; the consent policy does not change, so no new consent is needed.
   - **On the fork server it ends** by its own condition «the server is enlarged» (`R-156b`), once the fork bullet of decision 8 is implemented there (`R-156k`: in the fork). On the current production VPS it stays.

## Accepted risks

- **К3: the models see decisions of any project, whole, with quotes** (`R-153z`): text of one client's document can go to the provider in a call about another client's document. It falls under `D-291` and closes `DECISION-MEMORY-01` Q4. The delivery journal is `KEEP`, holds no text and survives the erase of a project.
- **The encoder is shipped without a measurement.** Its 3 177,9 MiB peak sits next to services with no memory limit; the first night is the test, and a lack of memory is loud (a skipped window, a status the administrator sees), never silent. Observed at first operation: the number of findings per run after «один список», the encoder's peak and the window's length, the length of the intent tail, the share of findings outside the critic window, and how Codex handles norm images.
- **Block grounding proves a place, not a content** (decision 7).
- **The replay's figures are a tool, not proof, until real decisions exist.** Thresholds start as the owner's «≥5, ≥90 %, 2 проекта» (`R-153ad`) and the section switch is the real gate.

## Consequences

- Cost: the user-visible list grows; the release note says so, that for «один список» runs «проверено» and «ждут решения» count differently, and that the v3 queue is re-consented.
- Cost: rollback is a switch for new runs; a migration with rows in the new tables is not rolled back.
- Cost: compose gets its first memory-limited service and the host its first timer; `deploy.sh` checks the disk before the image build.
- Cost: «Разбор» gains a source chip and a mark per row, a collapsed queue and one line while vectors are missing; concepts per screen are counted in each UI task (`R-153f`).

## Alternatives considered

- **A resident encoder with database access** (`DECISION-MEMORY-01` section 3.6) — rejected for now: 3,2 GiB beside a run on a 4 GB host risks killing the run and the database; the end of temporary decision 2 reopens it.
- **A mark per row «Недоступно»**, **a new rail chip for «Прецеденты»**, **HNSW over the cases** — rejected: one line above the list, the state in «Разбор», an exact scan inside a section.
- **A model writing the mark or the reason** — rejected: a verdict is a human's (`ADR-0027` decision 3).
- **«Снять» for findings the critic did not review** — rejected by `R-153ar`.
- **A fallback search when a vector is missing** — rejected by `R-153ac`.

## Verification

Minimal and proportional (`R-153j`, `R-153an`): focused unit and contract tests per task, one narrow throwaway-database run for the migration, a read-only judge after each wave (J1 grants and recovery classification, the forget protection, the encoder's limits and the loud window skip; J2 the gate; J3 404, budget and injection; J4 «снять» conditions; J5 patterns and cross evidence); every guard has a test that can fail. A browser journey covers «находка-блок», «очередь» and «пауза векторов». A change a user can see is previewed in two themes at two widths before it is published.

## Revisit trigger

The end of either temporary decision; the first use with real client documents (`D-291`, `ADR-0028` decision 17); the encoder or the vectors move off the host; a model is allowed to write a mark, a reason or a verdict; the legacy route is removed.
