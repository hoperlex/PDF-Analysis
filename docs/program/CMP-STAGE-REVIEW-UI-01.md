# CMP-STAGE-REVIEW-UI-01 — connected stage review and launch UI

Task: [CMP-STAGE-REVIEW-UI-01](tasks/CMP-STAGE-REVIEW-UI-01.md). Initial base `f4f6e1ec`; root integrated the C4 provider/read seams up to `656d84e3` before this UI commit. API `1.13.0` and migration `0042` remain owned by the seal/integrator. Heavy gates and browser windows are deferred under the owner's direct 2026-10-30 instruction.

The new `stage-changes` widget renders exact class/category/system sections and separate before/after evidence panels, including side-specific absence uncertainty and PDF callbacks. High-level synthesis appears first with explicit server decisions; detail-only and insufficient-context results retain their own labels. SERVICE_STRUCTURE is collapsed and has no expert verdict. Cards retain carryover/stale state and lazy verdict history. Rejection requires a nonblank reason; edits pin the original server verdict revision. Bulk save uses bounded 500-update transactions with a distinct retained retry key per request; after a later failure, saved drafts clear while unsaved drafts and their request keys remain. Current cards refresh when the running chain completes.

`StageJournal` uses the backend's exact `{key,label,rows:StageChangeCard[]}` groups for designation/section/system. Malformed groups refuse instead of becoming an empty report. Excel/PDF/HTML use the generated Blob clients and existing download sink with object-URL cleanup. The raw-difference section shows immutable difference identities/text and exposes an optional raw-evidence callback; missing historical fragments are labelled unavailable rather than treated as empty source text.

The new `stage-run-controls` widget reads actual full-run history, excluding deterministic text-only recomputations from its latest-full selection. It renders the seven-step strip, state/date/counts/staleness and supports start, restart, cancel and resume. AI starts display the actual routed estimate and require consent to that digest; a full chain can start with cached AI answers and zero new calls. Resume estimates include the persisted run ID and effective revision after repair. Command keys survive uncertain responses. Automatic repair history supports keyed undo with a freshly read current map revision.

Selected-pair batch controls read current maps, obtain each AI estimate/consent, start an ordered durable queue and poll its actual server state. They pause, resume and cancel the queue and reopen its child runs. The catalog can recover a batch from a latest run's server `batch_id`. Every row retains completeness controls and adds single launch/state/date/exact server card counts. Assembly creation uses real project documents and a separate explicit pair confirmation. Editing reloads real membership, pins `member_revision_no` from the first edit, and never computes a revision from active members; conflict recovery explicitly reloads and resets the draft.

Public interfaces:

- `StageChanges({runId,mayAct,onOpenEvidence,onOpenRawDifference?})` and `StageJournal({runId,mayAct,onOpenEvidence})` from `@/widgets/stage-changes`.
- `StageRunControls({pairId,linkRevisionId?,runId?,mayAct,compact?,onRunChange?,onOpenBatch?})` and `StageBatchControls({projectUid,selectedPairs,mayAct,batchId?,onBatchChange?,onOpenRun?})` from `@/widgets/stage-run-controls`.
- `StagePairCatalog` preserves its required project/role props and adds optional `onRunChange` and `onOpenRun`. Initial history reads do not select every catalog row through the callback.

An assembly created before pair confirmation remains a real server assembly if the user leaves that flow; no assembly-list operation is invented.
