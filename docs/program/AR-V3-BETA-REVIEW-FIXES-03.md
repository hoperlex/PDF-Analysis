## Limits

- A **hand-made map** (items and `mapped_document_ids` only, as the earliest tests built) is refused as `map_invalid` now that it must carry `norms_snapshot_id` and a `designation` on every target. Maps written by `map_pack` always do.
- The `synthetic` flag and the snapshot consistency are early, DB-free refusals, not forgery controls: whoever writes the map writes the flag. The control is the library (it compares the map's identity with the request's snapshot and reads that snapshot from the database) and the reviewer's independently computed digests.
- F3: a stranger's **empty regular file** that appears at one output name between the existence check and the create, plus an interrupt in the same instant, is removed as if it were the call's own unwritten leftover. A stranger's file with content, or any file the create itself reported as existing, is never removed. A SIGKILL in the middle of a write still leaves a partial pack.
- F3 was proved by injection; the real signal timing is not reproduced (the window is a few bytecodes).
- The `designation` comparison is exact text (no folding), as the library uses the label verbatim. A reviewer whose label differs only in case or a trailing space gets a refusal, by design.
- Query vectors are still not compared with the map (their digests are the reviewer's recomputation, runbook step 4).
