# Десятый блок: параметры как контекст изображений

База `origin/dev=f68f832ba9ce0149ec950248c86b921aedfcde92`, API1.14.0/migration0044. Task `BLOCK10-INT-1030`, root единственный автор, публикация dev /owner deploys.

Свежая отдельная `project_parameter_context_policy` связывает уже существующий паспорт с визуальным проходом: восемь зарезервированных запросов параметров выполняются перед новыми изображениями, затем сохранённый результат/ответы используются повторно. Новых логических модельных шагов нет. Прежние команды без поля сохраняют порядок и содержимое запросов. Для нового пути неудачный паспорт сохраняется с явным failed-status и не повторяется автоматически между визуальным и текстовым проходами; неизвестный оплаченный исход по-прежнему блокирует новый расход.

В один визуальный запрос входят до16 полных предварительных кандидатов в пределах16000 символов закодированного JSON-контекста. Предпочтение получают источники тех же физических страниц; остальные отбираются стабильно. Не вместившийся кандидат целиком пропускается с фактическими счётчиками охвата, без обрезания цитаты до якобы полного факта. Контекст содержит реальные значения/единицы/предметы, цитаты/страницы/диапазоны и статус паспорта; он явно не является экспертным решением, нормативным требованием или визуальным подтверждением.

Новая политика заранее резервирует только дополнительный **вход** —70000 токенов на каждый из максимум2 визуальных запросов локального16-source окна. Число model calls и выходные квоты не увеличиваются. Decoder сохраняет исходную схему ответа и source allowlist визуального пакета: context_fact_id не становится новым разрешённым source_id. `dataclasses.replace` сохраняет реальные image_bytes/images_bytes и дескрипторы PNG; изменяются лишь текст/хэш свежего запроса. Обычные durable custody, idempotency, measured cost, отмена и unknown-effect guards остаются.

Контекст имеет собственный bundle hash, связанный с замороженным parameter bundle. Оба фактических bundle сверяются до нового раннего оплаченного действия. Старые coverage/core/workflow/project_parameters.py не менялись этим блоком; отсутствующая новая политика не подменяет запросы/ответы истории. Свежий `AUDITMANAGER_PROJECT_PARAMETER_CONTEXT=0` исключает новый порядок/контекст и его входную оценку.

Квитанция сохраняется до вызова, затем отдельно отмечает наличие сохранённого ответа и replay. UI показывает «подготовлено» и «получен ответ» раздельно, с реальными IDs/hash/охватом и страницами по25 квитанций; это не утверждение, что модель использовала каждый факт или подтвердила его по изображению. MD/HTML и существующие полные JSON/ParameterReceipts XLSX сохраняют весь контекст независимо от фильтра. Для свежего пути локальные окна больше не рекламируют копию глобального8-call паспорта.
