## 2. The thirteen operations and what each does

All thirteen start with the adapter's own module flag (`versions`; with it off every operation answers `503 dependency_unavailable` naming `comparison_modules`, as the sealed stubs did), then the service repeats the flag, then every write checks the expert role and claims its idempotency key through `CommandRepository`.

| operation | what it does |
| --- | --- |
| `streamComparisonSeriesSummary` | reads the series through `SummaryReader` and streams the deterministic MD (`text/markdown`); the same data give the same bytes (time of the data in UTC, sheets sorted); `409 conflict` with reason `comparison_summary_unavailable` when the series has nothing to summarise |
| `listComparisonReports` | a page of the series' reports, newest first, tombstones left out; the state is derived from the job (`derived_state`), a draft carries its estimate recomputed on read |
| `createComparisonReport` | a `draft` from the summary (or from the stored file of an earlier report), kind `client` by default; **no model call**, an estimate only |
| `uploadComparisonReportSource` | raw `text/markdown`, at most 20 MiB; refused (`422 validation_failed`, field `content`, constraint `comparison_report_source_invalid`, nothing written) when empty, over the limit, not UTF-8, without a transition heading, or naming more transitions than the series has |
| `getComparisonReport` | the report with its parts, its artifacts (`report_pdf` and `source_md` only; the stored text `report_text` is internal), its job and, for a draft, its estimate |
| `startComparisonReport` | the consent: `draft -> queued` and the job in one transaction through the core (`ComparisonAiJobService.start`), the report row holding the job's id; the core key is derived (`sha256(report_id:key)`); a stale digest is refused by the core |
| `cancelComparisonReport` | cancels the job through the core; a finished part stays; a draft is refused with `comparison_report_state` (the contract's text, although the table allows `draft -> cancelled`) |
| `continueComparisonReport` | a paused report resumes through the core (`resume`, under a new consent with the left-estimate digest after an overrun or a changed route); a partial, failed or cancelled one is finished under the consent it already holds (`finish`, «Досчитать»); the finished parts are reused; a draft, queued, running or completed report is `comparison_report_state` |
| `rebuildComparisonReportPdf` | «Пересобрать PDF»: the stored text is rendered again in the child and a new artifact is appended; **no job, no model call** |
| `deleteComparisonReport` | a tombstone (`deleted_at`); a report that is queued or running is refused, and a paused one too (stricter than the contract) |
| `prepareComparisonClientReport` | «Подготовить отчёт для заказчика»: a client draft whose `prepared_from_report_id` is the analytic report; its parts are reused where the content key is equal |
| `streamComparisonReportPdf` | the newest `report_pdf` artifact from the blob store |
| `streamComparisonReportSourceMd` | the report's source MD from the blob store |

The work: a report job has one item per transition (priority by discipline, `comparison_report` kind, dedupe key `<job>:<unit_key>`) and a **final item** (priority -50) that waits until every other item of the job has ended, then builds the document, writes the PDF in the child, stores the blobs and moves the job to `completed` (or `partial` and no PDF when a unit is unfinished). Every model call goes through `ComparisonModelCaller.call`: the journal row is `prepared` before the adapter is touched and settled after it; the ×1.2 overrun pause and the USD 10 per job and 50 per day ceilings are the wrapper's, and a pause is `pause_for_spend` of the core. The lane writes no row of `comparison_ai_job`.

Client kind: one call per transition with the discipline's priorities; the program check drops every point whose number, designation (mark) or direction the transition's facts do not confirm, counts the drops in the recall line printed on every page, and the PDF holds one chronological table. A transition with no description is finished by the program (no call). Analytic kind: analyst, then verifier (every claim needs a verdict; it may only cite what it was shown), then composer (its numbers are checked against the facts and it is asked again with the program's remarks); a number that no fact holds is printed as unconfirmed. Reuse: a finished part is found by the content key `sha256(prompt version, kind, project, model, discipline, transition sha, records flag)`, in the report itself after a continue and, when the report asks for it, in an earlier report of the same project.

## 3. Decisions this lane made (each is one place to change)

1. **One live job per report is the report row's.** `link_job` is one statement (`UPDATE ... WHERE state = 'draft' AND comparison_ai_job_id IS NULL`) inside the core's start transaction; a second start is `409 conflict`, reason `comparison_report_state`. M7 shows the guard fails without it.
2. **The draft's estimate is recomputed on every read.** `estimate_digest` is frozen at creation by the table's trigger, so a refreshed estimate cannot be stored; the read recomputes it (and falls back to the stored one on `dependency_unavailable`). The consent carries the digest the core computes.
3. **The PDF is checked inside the child.** `pypdf` must not load in the API process (`test_api_never_loads_pdfium`), so the child renders and then runs `check.py`; a PDF that fails its own check is not stored and fails the report with `pdf_check_failed` (M17).
4. **Transitions with no description are finished by the program**, not asked of the model (deviation from the original, which asked); they are printed as undescribed.
5. **The analytic composer** accepts remarks that are only fixable after the last attempt and prints them as `check_warnings` in the PDF (the original stopped); a hard remark still fails the unit.
6. **A cancel of a draft is refused and a delete of a paused report is refused** (the latter stricter than the contract; one `if` to relax).
7. **The client kind's last unit does not pause for an overrun** when no other live unit exists (a resume of a job with nothing left would deadlock).
8. **Fonts:** DejaVu Sans (Regular and Bold) from Debian `fonts-dejavu-core` 2.37-8; the licence file is next to them and lists their sha256 sums, which a unit test checks (`test_the_package_holds_the_font_and_its_licence`). `Q-CMP-9` named reportlab and a free Cyrillic font.
9. **`SummaryReader` is SQL in the report package** (the series reads are not public as one query); it reads `comparison_sheet_description` and `comparison_spec_comparison` read-only and renders nothing for them while they are empty.
