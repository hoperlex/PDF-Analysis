# EXEC-ENV-OPENROUTER-01 — базовый OpenRouter в назначениях

## Результат

При `AUDITMANAGER_PROVIDER_SOURCE=database` рабочий процесс принимает полный
набор `PROXY_LLM_BASE_URL`, `PROXY_LLM_TOKEN`, `PROXY_LLM_MODEL` из закрытого
`provider.env`. При первом старте он создаёт обычное HTTP-подключение
«OpenRouter (из окружения)», сохраняет ключ в зашифрованном виде и ставит
проверку в очередь. После успешной проверки подключение доступно в
«Исполнители → Назначения». Действующее назначение Codex не меняется.
Повторный старт не создаёт дубль и не перезаписывает настройки, изменённые
администратором. Архивированное подключение не восстанавливается само.

Для такого подключения применяется `openai_chat`: проверенный PNG идёт в
`image_url` с data URL. Тесты покрывают путь OpenRouter `/api/v1` и содержимое
изображения. Реальный платный вызов OpenRouter не выполнялся.

## Проверки

- Настройки источника, запуск worker и границы старта: **23 passed**.
- HTTP-вызов через локальный тестовый шлюз, включая PNG и `/api/v1`: **23 passed**.
- Readiness для источника, режима, бюджета и ключевого кольца: **15 passed**.
- Python compile и `git diff --check`: OK.

  Интеграционный тест добавлен, его следует выполнить в lane с PostgreSQL.
- Полный `make gate` отложен для итогового beta-кандидата по `R-135`.

## Контракты и ограничения

OpenAPI `1.1.0`, stage registry, crop manifest, migration head
`0031_executor_pull_channel`, root dependencies и lock files не изменены.
Нет нового API, маршрута или автоматического переключения с Codex.
`PROXY_LLM_*` служат только для первоначального создания подключения:
после этого его настройки и ключ изменяются через UI. Неполный набор и
`ANTHROPIC_API_KEY` при источнике `database` отклоняются при старте.
Выбор доступен после успешной проверки текущего ключа. Поддержка PNG в
транспорте не запускает стадию анализа изображений: для неё нужен
утверждённый промпт W56b и политика доказательств. SSH-команда и SSH-туннель
по-прежнему не обслуживаются.

## Интеграция и откат

На хосте заполнить три `PROXY_LLM_*` в `provider.env` реальными адресом,
ключом и точным именем модели, которую сообщает шлюз. Сохранить
`AUDITMANAGER_MODEL_ID` соответствующим закреплённому тарифу модели
(`claude-opus-5`, `claude-sonnet-5` или `gpt-6-sol`), если нужен не
стандартный pin. Оставить
`AUDITMANAGER_PROVIDER_SOURCE=database` и `AUDITMANAGER_PROVIDER_MODE=live`,
перезапустить worker. В «Исполнители → Подключения» дождаться результата
проверки, затем при необходимости выбрать OpenRouter в «Назначения».
`provider.env` остаётся доступен только worker; токен нельзя передавать
через UI или чат. Для отката убрать три переменные: созданное подключение
остаётся в БД и может быть архивировано после снятия назначения.

`origin/main` не меняется. Запретные hotspots (`contracts/**`, миграции,
composition root, root lockfiles, глобальные стили) не затронуты.
