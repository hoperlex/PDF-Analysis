# CMP-VC-QUEUE-01 — очередь запуска сравнения

Интегратор выполнил задачу на `integration/compare-modules` после слияния AI-JOBS, SPEC, AIPAIR, AISHEET и REPORT. Вход: контракт API `1.11.0` (176 путей, 198 операций, 517 схем), миграция `0040_comparison_ai_reports`, исходная точка `4c8b3e89`. Файлы задачи: [`tasks/CMP-VC-QUEUE-01.md`](tasks/CMP-VC-QUEUE-01.md), [`CMP-SEAL-C2.md`](CMP-SEAL-C2.md), [`dispatch/CMP-WAVE-C2.md`](dispatch/CMP-WAVE-C2.md).

## Результат

- Семь запечатанных операций обслуживаются `ComparisonLaunchQueueAdapter`. Проверка модуля остаётся первым действием каждой операции; сервис повторяет её до обращения к данным.
- `ComparisonLaunchQueueService` хранит очередь проекта и записи шагов в двух таблицах миграции 0040. Команды эксперта используют `command_record` и возвращают тот же сохранённый результат при повторе ключа. Чтение установки проецирует `ComparisonAiJobService.waiting()`.
- Фоновая работа `comparison_launch` берёт по одной записи проекта. Перед каждым изменением она доказывает владение попыткой; следующий шаг выбирается только после завершения предыдущего. Ненужный шаг получает `skipped`. Отсутствующее или устаревшее согласие даёт `needs_consent`, и очередь переходит к следующей записи. Начатые дочерние шаги используют ключ от `comparison_launch_entry_id`.
- Pause оставляет текущий шаг до окончания; resume снова запускает работу; clear удаляет всё, кроме работающего шага; remove принимает только `waiting` или `needs_consent`.

## Ограничения и интеграция

- У контракта нет команды, которая добавляет новый digest к записи `needs_consent`. Эксперт может удалить запись и поставить шаг вновь с текущим digest; отдельная команда может быть запечатана в C3.
- Дочерние сервисы матрицы, AI и отчёта принимают собственные ключи, но не принимают fence внешней очереди. Проверка владения стоит непосредственно перед их вызовом и перед записью результата; при потере lease между ними дочерний сервис может принять команду. Повтор не создаёт второй дочерний запуск благодаря постоянному ключу. Усиление сквозного fence требует отдельного FIX с владением этими сервисами.
- Исполнители AI из C2 пока не имеют рабочего live model binding в композиции worker (отмечено отчётами AIPAIR, AISHEET, SPEC и REPORT). Очередь делегирует их запускающим сервисам; она не обходит маршрутизацию и не делает модельный вызов сама.
- Обзор C1 пока показывает шаги 4, 6, 7 как `not_applicable`; это зарегистрированное исправление C2 FIX, не изменение состояния данной очереди.

Интегратор должен сохранить регистрацию `comparison_launch_handler` в `HANDLER_FACTORIES`, остальные обработчики C2 и общий состав таблиц. Ни `contracts/**`, ни миграции, root lockfiles, глобальные стили, `web/**` и `infra/**` этой задачей не менялись.
