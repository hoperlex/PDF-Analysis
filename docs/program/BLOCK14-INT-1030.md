# Четырнадцатый блок: плотные native-страницы

База `origin/dev=6f907ece3f747214bbcba265974b2d0df779ebe3`, API1.14.0/migration0044. Task `BLOCK14-INT-1030`, root единственный автор, dev /owner deploys.

После снятия общих лимитов одна физическая страница с текстом больше модельного окна всё ещё отклонялась целиком. Свежая независимая `native_page_piece_policy` разрешает обычному текстовому этапу раздела обработать такой источник частями. Источник prepared.text_layer не переписывается, номера страниц не заменяются искусственными, Unicode-последовательность и нормализация документа остаются исходными.

Новый чистый planner включается только при действительно слишком длинной native-странице. Он строит полное последовательное покрытие текста с учётом настоящих физических страниц, пустых страниц, рамки1024 символа и512 символов на заголовок страницы. Части не пересекаются и не оставляют пропусков; отдельное окно может начинаться или заканчиваться внутри страницы. Fitting recognised/OCR-блоки остаются целыми и отдельным контекстом; слишком большой такой блок по-прежнему отклоняется, распознавание этим блоком не добавлено.

Отдельный binder валидирует полный plan/reply cohort и ищет цитату только в пересечении реально переданного окна с названной исходной страницей. Совпадение в другой части той же страницы не разрешает якорь. Разрешённая цитата получает настоящий document-global Unicode range, затем проходит прежнюю проверку исходного текста и B4 evidence gate. Legacy window_anchor/window_cohort не ослаблялись. В частичных окнах предложения категории отсутствия остаются без доказательства и не становятся каноническими находками. Это консервативный запрет, не поиск отсутствующих сведений по всему документу.

Policy binds hashes нового helper, windows и windowed runtime; фактическая реализация проверяется до ранних платных визуальных действий. Свежая оценка резервирует консервативное число вызовов/вход/выход для полного next-fit покрытия без прежнего искусственного page_count потолка. Оценка учитывает возможное экранирование recognised text и page framing и может заметно превышать фактически понадобившиеся вызовы; неиспользованный резерв не расходуется. В режиме owner statistics сохраняется принятая uncapped authority, но операционный window bound берётся из новой оценки. `AUDITMANAGER_NATIVE_PAGE_PIECES=0` исключает новую authority/оценку для свежих запусков.

Согласие сохраняет собственную policy; provider binding переносит её вместе с принятым window/cost authority. Старые команды без поля сохраняют целые страницы и прежний отказ, без увеличения оплаченного плана. Trusted AR-v3/group procedures не включают новое правило; повторный trusted AR-v3 также исключён. Изменившийся helper требует нового согласия, а не молчаливой подмены запроса.

Каждое окно имеет прежний durable key, который уже включает точные глобальные границы, источник, профиль и request SHA. Сохранённые ответы/неизвестные оплаченные исходы сохраняют прежнюю дисциплину. Физическая страница считается полностью обработанной только если все её части получили несокращённый ответ. Scalar metrics показывают piece mode, число окон частичных страниц и страницы с неполными частями; ограничение межоконного текстового поиска явно сохранено. Канонические наблюдения и экспертные решения не объединяются между частями этим блоком.

Изменены новый `analysis/text/page_pieces.py`, `analysis/text/{windows,windowed,config}.py`, analysis public lazy seams, `runs/{preflight,cost_policy,executor}.py` и программные документы.
