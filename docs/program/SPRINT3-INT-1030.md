## V3 сравнения стадий

Новый режим сохраняется внутри уже существующего экспериментального engine. Глобальный Mapper получает идентичности всех принятых страниц и обозначенные репрезентативные выдержки. Полный текст передаётся далее ограниченными пакетами; ответ Miner может ссылаться только на фактически отправленные блоки. Непарные страницы имеют ограниченную область встречных кандидатов; отсутствие данных не превращается в доказательство отсутствия изменения. Dedupe и проверка параметров также выполняются пакетами с сохранёнными результатами.

Прежние16 страниц /80000 символов /400 фрагментов остаются историческим native-планом. Для новых стартов `AUDITMANAGER_STAGE_V3_PLAN=legacy` выбирает его; по умолчанию — `windowed-v1`. Переключатель новых запусков не переопределяет уже принятые команды и batch. Общий лимит запроса240000 символов и конечные budgets сохраняются.

Политика входит в frozen input/bundle и согласованную оценку. При этом fingerprint idempotency-команды содержит только прежние клиентские поля: повтор принятого запроса не зависит от смены default/env. Политика выбирается после `CommandReplay`, сохраняется в outcome и наследуется дочерним запуском. Повторный запуск не смешивает результаты разных bundle.

Длинные `before`/`after` представлены как помеченные отрывки. Метаданные хранят полный размер/хэш и полные источники; эксперт видит границу отображения и может обратиться к сохранённому оригиналу. Транспортные ограничения API и исходные детерминированные свидетельства не менялись.

## Аналитические отчёты по MD

Каждая часть имеет настоящий диапазон строк/символов, SHA источника/запроса и устойчивый ключ. Оценка перечисляет реальные части и резервирует по две допустимые попытки аналитика и проверяющего. Сырой оплаченный ответ сохраняется до разбора; завершённый ответ без сохранённой custody и неопределённый эффект блокируют новый расход. Уже сохранённый ответ повторно не отправляется.

Переход получает `analysis=done` и `verification=done` только после всех известных частей. Исходный MD остаётся побайтово прежним; факты и source ranges не заменяются префиксом. Большой одиночный переход больше не считается одним целиком помещающимся запросом.

План заранее выбирает способ сборки. Для многочастного результата программно включаются все сохранённые проверенные части и приложение покрытия. Небольшой одиночный результат может использовать модельный композитор с заранее зарезервированным входом. Нового расхода ради повторной программной сборки нет: общий AI-job core разрешает0-call только при явной capability аналитического report-метода; согласие, digest, маршрут, потолки, очередь и idempotency остаются обязательными. Клиентский отчёт остаётся прежним отдельным путём с одним вызовом на переход и прежними пределами.

Закрытый `ComparisonReportPart` по-прежнему выдаёт четыре счётчика фактов, marks и число предупреждений. Точные счётчики/диапазоны частей находятся внутри сохранённых facts и в сгенерированном PDF; поля API не переопределялись. Общие денежные потолки10долл./задание и50долл./день сохранены. У metered-маршрута большая оценка может быть отклонена до старта; unmetered-маршрут остаётся отдельным действительным вариантом. Длинная одиночная строка, чрезмерный JSON или ограничения PDF могут дать явный неполный результат.

Старый аналитический content key не подменяется новым: несовместимое продолжение требует свежего отчёта до нового модельного расхода. История и прежние ответы сохраняются. Проверка неизвестного исхода/ответа без custody не является доказанным механизмом recovery, пока не выполнено отложенное окно исполнения.

## Строгий свод обычного анализа

`result.observations` и исходные окна остаются неизменными. Дополнительные `consolidation` и `consolidated_observations` группируют лишь записи с совпадающими title/description/category, полным исходным текстом/рекомендацией primary-предложения при наличии и общим привязанным source ID. Противоречивый или отсутствующий источник сохраняется отдельной записью. Нормативные оценки, критика и предложения корректора не сливаются в выдуманный общий вердикт.

Каждый origin ссылается на индекс/ID/окно и SHA той же исходной записи. UI сверяет привязку с тем же неотфильтрованным ответом; разные исходные рекомендации доступны раздельно. Старые terminal v3 результаты могут получить этот вычисляемый вид при чтении без backfill или новых модельных вызовов. Ошибка группировки явно делает этот вид недоступным, сохраняя все исходные записи.

Это отдельное представление предварительных наблюдений. Канонические findings, экспертные решения, их счётчики и raw comparison evidence не изменены. Группировка не расходует дополнительные модельные вызовы и не добавляется к платным промптам.
