# Сравнение сохранённых результатов двух прогонов

В существующий экран сравнения двух прогонов одной версии добавлено явное действие чтения самих результатов. Прежние факты/этапы остаются; можно загрузить более ранние страницы списка прогонов и выбрать другую пару. Новый маршрут или API не создаётся.

По нажатию читаются все cursor-страницы опубликованных находок и сохранённый расширенный результат обеих сторон. Идентичности run/project/version, отсутствие повторных IDs/курсоров, число находок и терминальное состояние сверяются по полученным проекциям. Пределы: 20000 находок / 1000 страниц списка / 64 МиБ на прогон; есть прогресс и отмена. Нет подтверждённой публикации — нет выдуманного нуля. Недоступный расширенный результат не превращается в пустой список. Неоконченное расширенное исполнение требует повторного чтения после завершения.

Канонические находки сопоставляются по устойчивому `finding_uid`; сравнивается полный сохранённый текст/рекомендации/свидетельства и остальные поля наблюдения, кроме run-specific identity/provenance. Предварительные наблюдения сопоставляются строго по точным title/description/category, полному первичному тексту/рекомендации при наличии и настоящим привязанным источникам. Неизвестные/противоречивые источники не получают фиктивную пару. Повторы сохраняются и сопоставляются один к одному. Разные формулировки автоматически не объявляются одной инженерной проблемой.

Стороны отображают полный текст, фактические номера страниц, исходные записи/полученные оценки и ссылки на соответствующий прогон. Различия предварительных norm/critic/corrector-аннотаций сохраняются отдельно. Список фильтруется и показывается по25 строк; JSON/CSV/standalone HTML содержат весь полученный набор независимо от фильтра. JSON и HTML сохраняют полные материалы обеих сторон. Выгрузка больше64 МиБ явно отклоняется, без исключения строк; CSV экранирует формульные префиксы, HTML экранирует исходный текст.

Это сравнение анализа одной неизменяемой версии: «запись только слева/справа» не означает, что документ исправлен. Текущие экспертные состояния читаются как текущая проекция, без обещания атомарного/исторического снимка всех решений. Сопоставление не пишет экспертных решений или переносов и не выполняет новых модельных вызовов.
