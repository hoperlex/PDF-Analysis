# CMP-STAGE-PAGE-01 — connected four-tab stage workspace

Task: [CMP-STAGE-PAGE-01](tasks/CMP-STAGE-PAGE-01.md). Initial integration base `f24f09e7`; root additionally merged the generated C4 escalation/detail provider at `7d7425fb` while this lane worked. This commit changes no contract, shared polling or backend.

The module-gated stage page now mounts documentation, sheet map, project changes and final journal. A project-keyed workspace resets unrelated pair/run/focus state on project change. Pair and full-run selectors consume actual paginated server data and verify project/pair scope; deterministic recomputations are excluded from report selection. The catalog's single/batch callbacks open their actual run. The full run strip, launch/resume/cancel controls and repair history remain visible above the tabs.

Card and raw-difference callbacks read the run's immutable effective map revision, verify pair/run identity and check each target profile's version against the run pins before navigating. The sheet map accepts optional controlled pair/run and `StageMapFocus` props, selects the real profiles/anchors, highlights the matching row and opens a historical revision read-only when needed. Its current unsaved draft survives switching tabs and viewing a historical snapshot. Explicit return restores the current map. Profile reads/cache are shared with the existing viewer; no version-comparison identity is fabricated.

The stored-word provider calls `getStageProfileText` with abort propagation and projects original words into searchable line boxes, enabling phrase search before text recomputation. Persisted SAME/MOVED decisions add grey overlays only at high confidence, with complete known fragment IDs and valid side/actual-profile bindings under the current matching run/revision. Uncertain/conflicting references veto AI masks. The overlay metadata is separate from raw differences/exclusions, and stale/dirty views hide masks. Upload publication invalidates affected pair/run/map/evidence reads so stale results can be shown promptly.

Cases cover cross-pair/run refusal, actual before/after anchors, phrase search from stored words, current versus historical rows, read-only history, original move rules, AI overlay safety and raw-evidence retention. No browser, build, full gate or remote operation was run.

Root integration requires the public clients/widgets already merged in the branch; `StageSheetMap` remains compatible with older callers because all new props are optional. Stable page selectors are `data-stage-pair-select`, `data-stage-run-select`, `data-stage-tab` (documentation/sheets/changes/journal), `data-stage-selected-run`, and `data-stage-focused-row`. The C4 journey/static refresh now belongs to the separate seal-agent lane.
