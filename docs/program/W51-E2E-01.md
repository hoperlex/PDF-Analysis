# W51-E2E-01 — code handoff

Base: docs-only dispatch `be74b2a` on `origin/dev`; branch `agent/w51-e2e-01`.

## Implemented

- Added an identity continuation of the PC-01 browser journey. It consumes the completed
  write envelope and uses an administrator session to register a synthetic applicant,
  observe the pending refusal, approve with `expert`, check the new profile, record a
  verdict and assert the derived «Тестов И. П.» author label. It then removes the role,
  checks the next BFF 401, the disappearance of the exact BFF session-register row and a
  sign-in link on the 401 screen, signs in again, checks `permission_denied` on a new
  verdict attempt, archives the account and checks `account_referenced` on purge.
- A second synthetic application is rejected. Its sign-in refusal is compared byte-for-byte
  with an unknown account and the archived account. Zero-role approval is checked for a
  visible local refusal and absence of an API call; administrator self-archive is checked
  for `permission_denied`.
- The identity operations and expected statuses are declared in the PC-01 manifest and
  statically reconciled with the frozen OpenAPI surface. Generated applicant passwords
  and session-cookie values are excluded from the identity envelope. The server register
  path must be supplied at run time; an inaccessible register fails the journey.
- The manual recorder and runbook now include A13–A20 and the five W51 routes in A09.
  Historical `ALPHA-MANUAL-01.md` was not rewritten. The PC-01 README has the separate
  identity command.

## Contracts, risks and integration

No API/domain/event contract, migration, root dependency, BFF runtime or application UI
changed. `manifest.json` extends the acceptance enumerator only. The generated applicants
and their actions create real data when the continuation is eventually run, so its origin
must be an authorized writable test deployment.

The immediate 401 screen may lack the required sign-in link; the new journey asserts it
and will fail if absent. That UI is outside this lane and belongs to the later correction
stage. A `last_admin` conflict cannot be reached reliably through the ordinary UI while
self-demotion is refused first; an isolated QA fixture must verify it under `D-137`.
Neither observation is marked passed.

migrations, backend, application UI, root dependency/lock files, composition root, global
styles and historical `ALPHA-MANUAL-01.md`) are untouched.
