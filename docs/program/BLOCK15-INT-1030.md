# Пятнадцатый блок: параметры в комплексной сверке

База `origin/dev=7e4b3364a2e75f0123ca0551eb19e94ec592a214`, API1.14.0/migration0044. Task `BLOCK15-INT-1030`, root единственный автор, dev /owner deploys.

Ранее отдельный паспорт параметров передавался только в визуальный проход. Свежая независимая `project_parameter_review_context_policy` добавляет уже извлечённые значения в существующие комплексную сверку, машинного критика и предложения исправления — для локальных и межоконных запросов. Это не новые шаги модели и не повторное извлечение паспорта. Новый путь выбирается только при batched-v1 и уже запланированном раннем B10 паспорте; отключение визуального early-context не меняет порядок ради этого дополнения.

В запрос входит до16 полных кандидатов, в пределах16000 символов кодированного контекста. Предпочтение имеют значения с реальных страниц текущего пакета; остальные выбираются стабильно. Целая запись, не помещающаяся в предел, пропускается с фактическими счётчиками, без усечения цитаты до якобы полного факта. Поля сохраняют исходные value/unit/subject, точные цитаты/диапазоны и parameter source/manifest hashes. Это предварительные подсказки о типе объекта и условиях, не нормативные пороги или утверждённый паспорт.

Система по-прежнему принимает output source_ids/source_evidence/proposed_source_ids только из исходного пакета запроса. `context_fact_id/context_source_id` не создают новых разрешённых ссылок; глобальный поиск дополнительно сохраняет проверку настоящих цитат из обоих удалённых окон. Критик и corrector сохраняют закрытые схемы, исходные наблюдения и отдельные рекомендации. Нормативный проход этим контекстом не расширяется; expert/canonical authority не добавлена.

Отдельный helper hash связан с действительным parameter bundle и проверяется до раннего платного действия. До свежего согласия резервируется70000 входных токенов на каждый уже запланированный local/global запрос трёх процедур; model-call/output quotas не увеличены. Владелец statistics mode сохраняет собственную uncapped authority и измерение расхода. `AUDITMANAGER_PROJECT_PARAMETER_REVIEW_CONTEXT=0` исключает только новое дополнение и его входную оценку для свежих запусков. Прежние отсутствующие флаги сохраняют прежнее содержимое запросов.

Квитанции содержат фактически переданный контекст/IDs/hash, request-prepared, полученный ответ и replay раздельно. Они собираются в `project_parameters.review_context_policy/review_context_receipts`, с областью local/global. UI показывает страницы по10 квитанций; MD/HTML/JSON и существующий полный ParameterReceipts XLSX сохраняют все данные независимо от страницы/фильтра. Предоставление значения не подтверждает, что модель его верно использовала.
