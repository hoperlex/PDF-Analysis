## Scope

- Select exactly five synthetic/anonymized golden journeys and an edge-case matrix.
- Reconcile the greenfield Bible, the immutable ADR-0001–ADR-0018 baseline and any
  newly indexed superseding ADR against accepted behavioral evidence and the pinned
  refactoring architecture source.
- Advance domain identifier/state/error drafts without implementing them.
- Define one target stage registry and strengthen versioned analysis packages.
- Make legacy-vs-target divergence explicit and evidence-backed.

## Required owner decisions

The architecture task prepares decision records, but the following remain
`pending_owner_approval` until the repository owner explicitly accepts them:

1. `PD-01`: expert correction/revocation creates a new append-only event and changes
   projections; it does not copy legacy overwrite/delete behavior.
2. `PD-02`: one versioned target stage registry is authoritative; conflicting legacy
   declarations are aliases/evidence, not competing sources of truth.
3. `PD-03`: `AuditRun`, `Job` and `Attempt` are distinct, and current-attempt
   authority/fencing is mandatory; this extends partial legacy token/epoch behavior.
4. `PD-04`: graphic/vector comparison is future greenfield scope, explicitly absent
   from legacy parity and not fabricated in W0 fixtures/contracts.

Rejection or ambiguity in any decision stops semantic contract freeze; agents record
the mismatch and do not choose on behalf of the owner.

## Non-goals

- No production backend/frontend code, migrations, composition or infrastructure.
- No further root dependency/lock changes and no application vendor/runtime choice;
  the completed validation-only lock is a frozen read-only wave input.
- No production/customer payloads, credentials or mutable legacy checkout evidence.
- No OpenAPI/comparison/event contract expansion in this wave.
- No CP-00 tag or checkpoint claim; W0.3 integration/ratification remains separate.

## Integration order

1. Verify each handoff and allowed-path diff independently.
2. Review golden selection against the accepted inventory and sensitive-data policy.
3. Review architecture dispositions and present `PD-01`–`PD-04` to the product/domain
   authority for explicit approval/rejection.
4. Reconcile domain and analysis meanings with approved decisions. Semantic mismatch
   opens a blocking contract fix; consumers do not fork terminology.
5. Run provisioned bootstrap/schema/example gates and independent consumer review.
6. Only after acceptance record the W0.2 candidate contract set for W0.3
   ratification. No tag is created here.

## Automated gates

- One-time clean-checkout provisioning uses `python3 -m venv .venv/bootstrap` and
  `.venv/bootstrap/bin/python -m pip install --require-hashes --requirement requirements/validation.lock`.
- `.venv/bootstrap/bin/python scripts/validate_bootstrap.py` exits `0` with
  standalone `PASS`; no gate relies on ambient site-packages or ephemeral `/tmp`.
- Every committed JSON fixture/example parses; schema-backed examples validate.
- Golden journey IDs/count/provenance checks pass with no production payloads.
- Domain prefixes/states/errors and analysis registry/package checks pass.
- Internal Markdown links and `git diff --check` pass.
- Each task changes only its exact allowed paths; forbidden hotspots remain unchanged.

If the locked validation environment is absent or unusable, validation stops with
an actionable failure. There is no ambient or unpinned dependency fallback.

## Manual/checkpoint impact

- Repository owner records decisions for `PD-01`–`PD-04`.
- Independent reviewer samples all five golden journeys, all architecture ADR
  dispositions, critical state transitions and the complete legacy-stage alias map.
- W0.2 supplies inputs to W0.3; it does not itself satisfy the CP-00 manual runbook.

## Stop conditions / rollback

- Stop on unresolved owner semantics, unsupported legacy claim, sensitive fixture,
  ambiguous authoritative writer, mixed contract versions or silent fallback.
- Stop if either contract family edits the other's files or consumes an unaccepted
  draft as frozen.
- Rollback is lane-local before freeze: revert only the rejected docs/fixture/contract
  task. After a recorded freeze, use the formal freeze-break procedure and version
  update; no bypass feature flag applies to contract/evidence gates.
