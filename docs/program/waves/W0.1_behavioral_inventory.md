## Integration order

1. Integrator verifies each handoff against its task file and its allowed-path diff.
2. Independent reviewer reviews the QA implementation and behavioral inventory
   without modifying either artifact; findings are returned to the respective owner.
3. QA owner and BHV owner address findings in their own allowed paths and re-run
   task checks.
4. Integrator runs the combined documentation/link/bootstrap gates and records any
   environment prerequisite explicitly.
5. Product/domain authority reviews material semantic contradictions or synopsis
   corrections, if any.
6. Once `W0-BHV-01` is accepted, integrator may materialize/open `W0-BHV-02`,
   `W0-ARC-01`, `W0-DOM-01` and `W0-ANA-01`. `W0-QA-01` remains dependent on the
   later domain and analysis tasks.

## Automated gates

- `python3 -m unittest discover -s tests/contract -p 'test_validate_bootstrap.py' -v`
  exits `0` and covers missing-`jsonschema` behavior without uninstalling packages.
- In an environment without `jsonschema`, `python3 scripts/validate_bootstrap.py`
  exits non-zero, names the missing dependency/action and never prints `PASS`.
- In a provisioned environment with `jsonschema`,
  `python3 scripts/validate_bootstrap.py` exits `0`, validates schemas/examples and
  prints `PASS` when repository content is valid.
- `git diff --check` passes.
- Each task diff contains only its declared allowed paths; no task changes a frozen
  hotspot or the legacy repository.
- The behavioral inventory contains the canonical 40-character legacy SHA, a
  discovery coverage ledger, evidence status for every capability row, and no
  copied secrets or production payloads.

The provisioned validator run is an integration gate. Because root dependency/lock
files are frozen in W0.1, a missing tool dependency is reported as a visible blocked
environment prerequisite rather than bypassed or silently downgraded.

## Manual/checkpoint impact

- Product/domain authority reviews any `supported`/`partial`/`not observed`
  contradictions with the synopsis and approves semantic changes, if proposed.
- Integrator confirms legacy evidence comes from the pinned Git object, not the
  current checkout or moving `main`.
- W0.1 does not close CP-00; it supplies input evidence for the remaining W0 waves.

## Stop conditions / rollback

- Stop BHV work if the pinned commit object is unavailable, if required evidence can
  only be obtained from credentials/production data, or if a semantic contradiction
  needs product authority. Mark the capability `unknown` and escalate; do not infer.
- Stop QA integration if the missing-dependency path can still print `PASS`, tests
  cannot deterministically exercise it, or normal validation has been weakened.
- A moving legacy `main` never updates this wave automatically; changing the oracle
  requires a separately reviewed traceability decision.
- Rollback is task-local: revert only the offending task's documentation or
  validator/test commit. No data migration, feature flag or runtime rollback is
  applicable because W0.1 creates no production behavior.
