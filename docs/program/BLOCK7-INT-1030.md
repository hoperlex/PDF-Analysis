# Седьмой блок: полные сохранённые СО в технических выгрузках

База `origin/dev=f4d722e5420699a0846b559d1410b7b7b683cdc7`, task `BLOCK7-INT-1030`. Единственный автор/интегратор — root; delegated-сессии остановились по usage-limit. Только исходный код и публикация dev, развёртывание выполняет владелец.

Существующий endpoint технического XLSX/HTML ZIP теперь читает не только сохранённые изменения СО, но и полные связанные `comparison_spec_extraction`: все позиции агрегата, в том числе неизменённые, candidate_positions частичного результата, полное покрытие и связанные проверенные части. Исходные строки/поля не обрезаются до600 символов публичной проекции. Новых моделей, PDF-разбора, сопоставления или экспертных решений нет; записи в БД не меняются.

Сборка идёт в уже существующем read-only repeatable-read снимке. Новый collector проверяет проект и реальные связи сохранённого сравнения, читает метаданные размера до больших JSON-значений, затем агрегаты и связанные checked batches. До4096 извлечений /100000 сохранённых записей позиций; это записи агрегатов/частей/кандидатов, не число уникальных физических позиций. Действуют 64 МиБ JSON /2000 переходов /2000 пар /50000 деталей и новый предел192 МиБ несжатых частей архива. Превышение явно отклоняет выгрузку целиком; строки скрыто не исключаются. Неполное/отсутствующее извлечение остаётся явно обозначенным, не пустой спецификацией.

Кэш извлечений специально имеет область project+source/prompt и может применяться к одинаковому тексту другой версии или комплекта этого проекта. Поэтому `origin_version_uid` сохраняет реальную версию создания, а `bound_version_uid` отдельно показывает сторону текущего сравнения. Перепривязка не подменяет происхождение и не считается повторной проверкой текста/PDF. Источники, полные значения и старые model/custody IDs сохраняются как записаны. Сырые provider replies не входят в эту выгрузку.

XLSX добавляет `ПозицииСО`, `ПокрытиеСО` и lossless `RawJSON`. Длинные значения в обычных ячейках обозначены отрывками со ссылкой на полный RawJSON; новые части ограничены30000 единицами UTF-16, без разрыва Unicode-символа. XML-недопустимые символы представлены JSON escapes в полном снимке, сохраняя исходные JSON-значения. Сводка содержит SHA256 полного UTF-8 JSON и порядок/число частей. Прежний отказ только из-за длинной отображаемой ячейки заменён явным отрывком при сохранении оригинала в RawJSON.

HTML ZIP дополнительно содержит `specifications/records.json`, `specifications/positions.csv` и `manifest.json` с фактическими SHA256/байтами файлов. Общий `records.json` сохраняет весь снимок отчёта, включая новые полные СО. CSV содержит позиции сохранённых извлечений; отдельные ещё не собранные side-coverage кандидаты целиком остаются в JSON. CSV экранирует формульные префиксы; JSON сохраняет буквальные исходные значения. HTML экранирует исходный текст; обзорные изображения сохраняют прежние ограничения и не называются цветным наложением. UI у существующих кнопок объясняет состав выгрузок и отсутствие модельных вызовов.
