# W55B-JUDGE-X — adversarial review of W55b (static)

**Reviewer:** a fresh-context subagent of the integrator, 2026-10-14.
**Subject:** `e1233e7a`; W55b range `9da3ea06..e1233e7a`.
**Verdict: REJECT.** The archive rules hold. Two findings are blockers. In each, a PDF of a few KiB that passes every rule of the bundle drives the API envelope or the run worker to gigabytes of memory. Two majors leave the new 250 MiB route and the crop count without bounds.

Probes are under `.local/judge/` (`p1`–`p9`, `python -I`, container-free). Each run is noted beside its finding. The figures were measured on this host, which carried other load at the time.

## Refuted

- Path traversal: `/`-absolute, drive-letter, backslash and `..` names are refused. A NUL or control character in a name is harmless: files are named by role, and the display name is scrubbed.
- Directory entries, `__MACOSX/`, Unix symlinks, encryption (bits 0 and 6, AES method 99) and any method other than 0 or 8 are refused before any data is read.
- Duplicate names are refused, also after case folding and NFC. `.PDF` and other unknown suffixes fail the member set. Multiple stems, and extra or missing members, are refused.
- A count above 8 is refused before the central directory is read, and the directory's size is bounded by that count.
- ZIP64 end records and per-entry fields are bounded by `_read`. Data descriptors are handled because the central sizes are used. A local name that disagrees with the central directory is refused.
- A truncated archive answers `bundle_unreadable`. There is no hang: every inflate loop is bounded by `remaining`, and the 64 KiB-boundary hang is fixed.
- Local entries the central directory does not reference are never read. A nested ZIP is never opened. Only the extracted members are stored, so there is no second ZIP reader and no parser differential.
- The padded-header ratio trick is caught by the consumed-bytes ratio, although only after the member has been inflated (X-5).
- `_blocks.json`, all refused with typed codes: wrong types, `NaN`/`Infinity`, `1e999` (it becomes inf and fails every numeric check), BOM, non-UTF-8, deep nesting (`RecursionError` is caught in ingest and in both stages), inverted or out-of-range coordinates, 1–2 or more than 64 polygon points, and a page-count mismatch.
- Duplicate JSON keys: both sides use the same parser, so both read the same value. No path to a 500 was found in `admit_bundle`.
- `_HEADER`, `DESIGNATION`, `_DOUBLED`: linear on adversarial lines; no catastrophic backtracking.
- Per-path cap: only `POST /projects/<one segment>/documents` gets 251 MiB. `%2F`, `%252F`, a trailing slash, `//`, case changes and query strings get 26 MiB or a 404. nginx's regex matches the same set on the normalised `$uri`.
- The nginx upload locations declare no `add_header` or `proxy_set_header`, so they inherit the four security headers. Both files were checked.
- BFF: a multipart body or one over 1 MiB is streamed. nginx always forwards a buffered body with a `Content-Length`, so `arrayBuffer()` only ever sees small bodies.
- Slowloris against the API's slots through nginx fails, because nginx buffers the whole body first (but see X-3 and X-9).
- The gate is per process with one uvicorn process (`serve.py`). Check and increment are not split by an `await`, and the slot is released in a `finally` on every exit.
- Crop and block reads are behind the app-wide seam with `_ANY_ROLE`. The product has no per-project ACL; the same holds for `getVersionBlocks`.
- A block id from another version answers 404: the lookup is in this version's manifest and the artifact's `version_uid` is verified. Unknown and forged ids get the same 404, and digests are verified.
- The PNG is served as `image/png`, with `nosniff` added by nginx. The bytes come from the product's own renderer, so content sniffing gains an attacker nothing.
- XSS: there is no `dangerouslySetInnerHTML` and no markdown renderer. Text and descriptions are rendered as React text, and `crop_url` is never on the wire. The crop `href` is built from validated ids with `encodeURIComponent`. A bidi override in recognised text stays inside its own block.
- Every `pypdfium2` call in `src` is made under `PDFIUM_LOCK`, in `envelope.py` and `geometry/render.py`. pdfplumber's `to_image`, which calls pypdfium2 itself, is used only by the norms CLI.
- Render pixel bomb: the bitmap is the clip, at most 4 MP. At the largest admitted scale (19 014 px/pt, a canvas of 11 M × 16 M), a render over text or over an image took at most 0.02 s and 83 MiB (`p8`).
- Temporary files are created with `mkstemp` (0600) or `TemporaryDirectory` (0700) and are removed on every Python exit path. Only a killed process leaves them (X-1).

## Notes

- X-1 and X-2 do not depend on the archive: the PDF member is tiny and inside every bound. Neither the input budget nor the 100 : 1 rule can see a PDF's internal compression or its page objects.
- X-3: the gate's `try_acquire` happens before any credential is checked, so `in_flight` counts strangers. W55a's search was gated after the seam; this gate is in front of it.
- X-7's inverse, a stage that is stricter than ingest, is the safer direction. The defect is that the version is accepted at all.

## Needs a live stand

- X-1: the RSS at which the API container is killed, which process the host's OOM killer chooses, and the `/tmp` leftovers after a restart.
- X-3: unauthenticated 260 MiB bodies through nginx (`client_body_temp` growth, slot occupancy).
- An early API answer (the busy 503, or `max_bytes` by `Content-Length`) while nginx or undici is still sending: does the client get the envelope, nginx's 502, or the BFF's "could not reach the API"?
- Whether Next propagates a browser abort to `request.signal` on the upload route.
- X-2 at 500 pages on the worker container. X-4 with a few thousand IMAGE blocks, including the 900 s fence while the stage thread runs on.
- The plan's figure of about 240 s for an accepted 250 MiB bundle, end to end.
