# Пятый блок: комплексная сверка между окнами раздела

Продолжение опубликованного `BLOCK4-INT-1030`, база `origin/dev=0dd8132806086044b9815842ef0cbf20eef34acc`. Владелец разрешил продолжать функциональные блоки и публиковать их в dev; развёртывание остаётся за владельцем. **Это исходный код без подтверждения исполнением:** тесты, сборка, компиляция/import, lint/typecheck, браузер, worker/DB и модели не запускались. Синтетика другой сессии не изменяется.

## Задача

Локальная комплексная процедура получает данные своего окна. Строгая группировка готовых наблюдений между окнами не выполняет новый поиск расхождений по удалённым листам. Этот блок добавляет отдельный ограниченный проход по настоящим текстовым источникам разных окон внутри одного раздела. Это не межтомовая координация и не новый графический/OCR-движок.

## Принятые границы

Для новых `extended-review-v3` с `batched-v1` и более чем 16 физическими страницами источника preflight может закрепить отдельную `global_cross_window_policy`:

```json
{
  "version": "cross-window-comprehensive-v1",
  "piece_characters": 20000,
  "call_limits": {
    "comprehensive_analysis": 8,
    "norm_verification": 8,
    "finding_review": 8,
    "finding_correction": 8
  }
}
```

Эти пределы относятся ко всему прогону и не умножаются на число локальных окон. До запуска оценка резервирует максимум 32 дополнительных обращения: по 100000 входных токенов на запрос, 6000 выходных для комплексного прохода и 12000 для остальных процедур. Реальные запросы остаются под денежным потолком; сохранённые ответы не создают повторный расход. Один лист с большим количеством portal-изображений сам по себе не создаёт удалённых текстовых окон и не получает этот дополнительный бюджет.

`AUDITMANAGER_EXTENDED_CROSS_WINDOW=0` отключает новую политику для свежих стартов. Отсутствие поля у ранее принятого запуска не разрешает новый расход. Вложенная политика проверяется по точным ключам, значениям и целочисленным типам; `bool` не заменяет число. Hash исходных алгоритмов/правил связывает принятые входы с действительной реализацией; изменившийся bundle требует свежего согласия до обращения к модели.

## Связь с результатами

Планировщик передаёт реальные фрагменты native/распознанного текста с идентичностью страницы/артефакта и диапазонами символов. Выбор кандидатов и пропуски ограничены и учитываются отдельно от локального покрытия. Комплексное наблюдение должно иметь проверяемые точные цитаты из обоих переданных окон. Новые исходные наблюдения сохраняются с происхождением; нормативная сверка использует имеющийся corpus, критика и предлагаемые исправления остаются отдельными машинными рекомендациями.

`result.global_cross_window` предоставляет фактическую политику, состояния, источники, покрытие и квитанции. Свод не превращает конечный набор рассмотренных пар в заявление о полной проверке всех удалённых листов. Все локальные оригиналы, исходные окна и экспертные решения сохраняются. Отчёты строятся из сохранённых материалов без новых модельных вызовов.

## Интеграция

Независимый слот интегратора [сравнивает сами сохранённые результаты двух прогонов](BLOCK5-SAVED-RESULTS-1030.md): все страницы находок, предварительные наблюдения, точные соответствия, различия, просмотр происхождения и полные JSON/CSV/HTML без новых модельных обращений. Прежний экран сравнивал лишь метаданные и счётчики. Текущие экспертные проекции не объявляются историческим снимком; отсутствие записи не означает исправления исходного документа.

Разделение областей: `BLOCK5-PLANNER-1030` — чистый планировщик; `BLOCK5-RUNTIME-1030` — вызовы/сохранение/обработка; `BLOCK5-EXPERIENCE-1030` — интерфейс и полные выгрузки. Интегратор владеет preflight, чтением согласия и публичными lazy-seams. API 1.14.0 / 233 paths / 259 operations / 620 schemas, migration `0043_stage_ai_generations` не меняются.

Не затрагиваются contracts, migrations, root dependencies/locks, composition root, global styles, tests или fixtures. Только обычная публикация в `origin/dev` с сохранением параллельных изменений владельца и read-back точного SHA. Main и deployment не входят в задачу. Проверки выполнения, восстановления, стоимости, источников и качества остаются в D-290; наличие кода не подтверждает готовность beta или равенство оригиналу.
