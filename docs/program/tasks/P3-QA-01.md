# Task P3-QA-01 — automated PC-01 journey, restart and idempotency evidence

> **Status: specified; not dispatchable.** Planned for P03, after all four slices are
> integrated. It tests slices and does not edit them.

## Outcome

One recorded-provider end-to-end suite proves the complete PC-01 journey, that restarting
the application and execution process loses no canonical state, that repeated commands
under one idempotency key create no duplicates, and that no S3 key reaches the browser.

## Non-goals

- No slice remediation: a defect is reported to its owner and never patched here.
- No live-provider assertion, no model-wording assertion, no performance or load target,
  no visual regression baseline, no cross-browser matrix beyond one pinned engine.

## Deliverables

- one end-to-end spec covering create, upload, run in recorded mode, progress, finding,
  page beside quotation, accept, reject, later comment, export and download
- a restart spec: stop and start the application and execution process mid-journey, then
  assert that run state, findings, ledger and export remain resolvable and that no run is
  displayed as still running
- an idempotency spec repeating upload, run start and decision append under identical keys
  and asserting exactly one version, run and decision. The export is **not** in this spec:
  it is a synchronous read that creates nothing, so it carries no idempotency key and there
  is no "exactly one export" to assert. It is covered instead by a byte-identity spec — two
  downloads of an unchanged run return identical bytes
- a negative spec set in which unsupported input, checksum failure, unavailable provider
  and ungrounded model output each render explicitly, with no fake success and no
  filesystem fallback
- a leakage spec asserting that no network URL, response body or DOM node contains the
  configured bucket name, the S3 endpoint host or an `s3://` prefix
- an anti-vacuity spec proving the suite fails when the API is stopped, so a green run
  cannot mean that nothing was exercised

  Expected: exit `0`.

## Integration contract

The integrator may rely on one green recorded-mode journey command covering the accepted
slice commits. This task certifies those commits, not its own unreviewed changes, and
never edits a slice to make a spec pass.

## Failure/idempotency/security cases

- Specs fail if a stale `running` run survives restart, if a duplicate aggregate appears,
  or if any decision value is overwritten rather than appended.
- Cleanup is scoped to generated test projects and versions and leaves the checkout
  unchanged. There are no generated exports to clean up, because the endpoint persists
  nothing.
- No credential or provider payload enters a test artifact or trace.

## Rollback / feature flag

Tests only. Revert the QA commit without touching product code or server state.
