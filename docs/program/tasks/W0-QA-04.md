# Task W0-QA-04 — a final-state contour that can distinguish a ratified checkpoint from an open round

## Outcome

An executable check contour that returns a truthful verdict on the **terminal** state of
CP-00, and that fails when given a tree whose records do not describe it. Today no such
contour exists: `artifacts/checkpoints/CP-00/check_state_records.py` models only "which
round is owed", so on the ratified tree it reports 14 findings that are a correct
description of a ratified checkpoint rather than defects, and the CP-00 suite passes 324
tests without noticing that `W0-INT-01`'s own ratification assertion fails.

## Deliverables

1. A final-state contour covering, each with a positive case, a negative case and a
   mutation that turns the check red:
   - **terminal state**: a checkpoint is either open-round, closed-accepted-round, or
     terminal-ratified, and exactly one is true of a given tree;
   - **live vs historical**: a dated primary report may state a superseded fact; a live
     record may not. The distinction must be structural, not a path skip list;
   - **tag integrity**: the annotated tag exists, is annotated, points where the records
     say, and has not moved relative to its recorded target;
   - **file and hash accounting**: every file the checkpoint claims, with its own hash,
     and the aggregate each hash rolls into — no aggregate whose members are unlisted;
   - **cross-gate agreement**: `W0-INT-01`'s required assertions and the architecture
     review's own fields agree, and the contour fails while they do not.
2. `docs/program/reviews/W0-QA-04.md` — an evidence-backed report: commands, real output,
   measured exit codes, the mutation table with green-before/red-after for every check,
   and every limitation recorded plainly rather than asserted away.

## Integration contract

The integrator can rely on: running the two discover commands on any candidate tree
returns a verdict that is true of that tree's terminal state; a tree whose live records
contradict its manifest, whose tag has moved, whose claimed artifacts do not exist, or
whose two ratification gates disagree, turns at least one named check red; and every
check has a recorded mutation proving it can fail.

## Failure/idempotency/security cases

- The contour must be re-runnable on the same tree with the same verdict.
- A check that cannot fail is a defect, not a pass: every guard carries its mutation.
- The contour reads the repository; it writes nothing outside its allowed paths and runs
  no Git command that mutates refs, the index or the working tree.
- Any subprocess it spawns must not inherit the ambient Git environment; see `E-06` in
  `artifacts/checkpoints/CP-00/known-risks.md` for why.

## Rollback / feature flag

Not applicable: the deliverable is test tooling. Rollback is reverting the integration
commit, which removes the contour and restores the previous suite exactly.

## Round three scope, added 2026-09-08 after the licence audit

**This section does not bear on round two's verdict.** It was written after round two's
bytes were pinned and dispatched for review, from an independent audit of the task graph
rather than of this deliverable. Round two is judged on the contract as it stood when it
was dispatched.

The audit measured a simulated ratification commit and found the CP-00 barrier
unreachable, on two blockers that both sit in the gap between this task — the sole writer
of `tests/**` — and `W0-INT-03`, which must write the ratification record and may not
touch a guard. Both are the defect this task has already closed twice, one constant
further along; neither is a new cycle of checking the checks, which the owner's decision
of 2026-09-04 forbids.

1. **`RATIFYING_TASK` is pinned to a superseded instance.**
   `tests/contract/test_cp00_candidate.py:100` fixes `RATIFYING_TASK = "W0-INT-01"`;
   `:1284–1287` refuses any other value; `TableExpectationTests` additionally requires the
   W0.3 wave plan to carry exactly one "CP-00 review ratification" row naming it alone, so
   rewording the plan does not help. `W0-INT-03`'s delta requires
   `ratification.task: W0-INT-03`. Isolated probe, one field changed:
   `'W0-INT-01'` → no finding; `'W0-INT-03'` → *"only W0-INT-01 may ratify CP-00"*.
   Resolve it the way `CHECKPOINT_TAG` was resolved at `:170` — from the ratification
   record and the wave plan's assignment row — and re-anchor `TableExpectationTests` to
   the series rather than to the instance. This is a **different constant and a different
   test** from the `:11342` item round two closed.

2. **The sandbox baseline is taken from a tree that no longer holds the anchors.**
   `_reset_to_the_frozen_tree` rebuilds every sandbox from `_freeze_commit`. After
   `39a3a64` that is a post-ratification tree: `CURRENT_STATE.md` has lost
   `"Nothing is ratified, nothing is tagged"`, the wave plan `` `W0-INT-01` is blocked ``,
   `docs/INDEX.md` `blocked`, and the `W0-INT-01` banner its blocked line. Measured: the
   integrated tree gives `_acceptance_problems` **0** in the sandbox, the simulated
   ratification **21**, cascading to about 135 of 141 contract failures — including
   `test_the_checkpoint_mechanism_has_a_reachable_published_state: no denial to update in
   docs/program/CURRENT_STATE.md`, the test written so that round nine's defect could not
   recur. A control that restores the denial sentence before the freeze moves the count
   139 → **140**: the next anchor fires, and there is no single-file repair. The two states
   are contradictory by construction — `_state_document_problems` requires the denial
   present when `ratified: false` and absent when `ratified: true`, at the same commit.

   Either normalise the state documents alongside the manifest when the sandbox flips
   `ratified: false`, or take the pre-ratification baseline from
   `REVIEWED_CANDIDATE_COMMIT` rather than from `_freeze_commit`. Without one of the two,
   **no freeze commit taken after `39a3a64` can ever produce a green ratification**, and
   `W0-INT-03`'s required `discover -s tests/contract` → exit `0` is unreachable.

3. **`tests/checkpoint/test_cp00_final_state_contour.py:415`** still carries a round-ten
   literal. The path is outside `POST_FREEZE_DELTA_CEILING`, so it can only be repaired

**Anti-vacuity applies to the repairs themselves.** Each of the two resolvers needs a
mutation that turns a named test red, on both a tree whose records say the superseded
value and a tree whose records say the successor; a resolver that agrees with the old
literal on today's tree and is never exercised on tomorrow's is the same defect wearing a
function call. State any row that is indistinguishable on one of the two trees rather than
smoothing it.
