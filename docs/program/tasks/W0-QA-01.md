## Outcome

Provide one reproducible consumer-side test and an evidence-backed review report that
the final CP-00 architecture, domain, analysis, event and golden artifacts agree at
their public boundaries without modifying any artifact under review.

## Ownership

- implementation/review owner: independent QA agent who authored none of the reviewed
  W0 contract, architecture or golden artifacts
- frozen-boundary governor: primary agent `/root`
- consumer: `W0-INT-01`
- product/domain authority: repository owner only if the review discovers a semantic
  choice; QA records the mismatch and never chooses it

## Deliverables

1. `test_cp00_candidate.py` validates cross-family invariants from repository data:
   exact contract-version key usage, schema/example validity, domain error enum parity,
   analysis reference integrity, golden assertion/checksum invariants, ADR/lint-rule
   coverage and absence of forbidden authority-token field names.
2. The test invokes or faithfully exercises the documented analysis Gates A–D; it
   must fail if any gate cannot be executed as documented.
3. Focused mutation cases cover at least: one run-lifecycle `rule_id` rotation, one
   swapped canonical `stage_id`, one renamed exclusion ID, one evidence observation
   moved to a site that lacks its name, one example naming an absent stage, one
   reintroduced domain `version` key and one event `schema_version` key.
4. `W0-QA-01.md` records the exact candidate commit, commands and results, mutation
   outcomes, SHA-256 hashes of the accepted analysis registry/name map and all known
   limitations. It explicitly records that remapping a name to another existing stage
   is semantic-review territory, not a referential-integrity guarantee.
5. The report gives a binary `ACCEPT` or `REJECT`; every rejection names the owning
   task to reopen.

## Required tests

- Command: `.venv/bootstrap/bin/python -m unittest discover -s tests/contract -p 'test_cp00_candidate.py' -v`.
  Expected: exit `0`; all positive and mutation tests pass against the recorded base.
- Command: `.venv/bootstrap/bin/python -m unittest discover -s tests/contract -p 'test_validate_bootstrap.py' -v`.
  Expected: exit `0`; validator regressions remain green.
- Command: `.venv/bootstrap/bin/python scripts/validate_bootstrap.py`.
  Expected: exit `0` with standalone `PASS`.
- Command: `git diff --check -- tests/contract/test_cp00_candidate.py docs/program/reviews/W0-QA-01.md`.
  Expected: exit `0` and no output.
- Command: `git status --porcelain -- tests/contract docs/program/reviews`.
  Expected: exactly two lines, `?? tests/contract/test_cp00_candidate.py` and
  `?? docs/program/reviews/W0-QA-01.md`, and nothing else under those two trees.

  Corrected by the integrator before assignment. The original form,
  `git diff --name-only <W0-EVT-01-integration-commit> -- tests/contract docs/program/reviews`,
  was unsatisfiable: both deliverables are new files, this task forbids `git add`, and
  `git diff` sees only tracked content — so it returns empty output whether the author
  wrote both files or nothing, and the stated expectation of two paths could never be
  met. The same defect was found and corrected in `W0-ARC-02`, whose author flagged it
  rather than reporting a green gate. `git status --porcelain` reports untracked and
  modified paths alike. Once the integrator stages the files, the `git diff` form
  becomes meaningful and is worth re-running then.

## Integration contract

`W0-INT-01` may rely on an `ACCEPT` report only for the exact commit and artifact
hashes it names. Any later contract, architecture or golden change invalidates the
report and requires rerunning the affected positive and mutation checks.

## Failure/idempotency/security cases

- A failed documented gate is a failed review even if an equivalent ad-hoc command
  passes.
- Mutation work happens only in temporary copies and never rewrites the candidate.
- Re-running against identical bytes produces identical invariant and hash results.
- Reports contain no payload bodies, credentials, environment dumps or mutable legacy
  checkout evidence.

## Rollback / feature flag

Tests and documentation only; no feature flag applies. Revert the two allowed paths if
the review method is defective. A rejected candidate is repaired by its owning task,
not by editing it from QA.

## Handoff

- changed files and exact reviewed commit
- positive and mutation commands/results
- new/changed contracts: none
- known limitations and explicit deferred inputs
- `ACCEPT`/`REJECT` plus owning-task routing
- proof that every forbidden hotspot stayed byte-identical
