A frozen, mechanically checked corpus of 12–16 measurable PC-01-envelope AR documents —
5 seeded plus 7–11 clean or representative controls — with a ground-truth manifest, plus a
separately counted set of 2–4 negative-envelope documents, and a session protocol and
recording schema under which two moderators produce comparable data.

## Deliverables

- 12–16 **measurable** synthetic AR PDFs, composed as exactly 5 seeded documents — each
  with its expected contradictions and placeholders by page and exact expected quotation —
  plus 7–11 clean or representative controls for false-positive pressure. The two ends are
  5 + 7 = 12 and 5 + 11 = 16, so the seeded count is fixed and the control count carries the
  whole range
- 2–4 **negative-envelope** documents — scanned, password-protected, over 30 pages, over
  25 MiB — counted separately from the measurable set, used only to observe explicit
  refusal, and excluded from every finding denominator and from every gate that counts
  measurable documents, G4 included
- `corpus_manifest.json`: per document the synthetic label, SHA-256, page count, byte
  size, seeded ground truth and provenance (`synthetic` or `anonymized`); an
  `anonymized` record carries anchors and hashes and never document bytes
- the session protocol and the per-finding, per-document and post-session recording
  schema as JSON Schema
- `tools/validation/corpus_check.py`

## Required tests

- Command: `.venv/bin/python tools/validation/corpus_check.py
  fixtures/validation/PC-02/corpus_manifest.json`
  Expected: exit `0`. Asserts for every measurable document: ≤25 MiB, ≤30 pages,
  extractable text on every page, declared SHA-256 matches bytes, every seeded quotation
  present verbatim at its declared page, provenance set, and no committed bytes for an
  `anonymized` record.
- Command: `.venv/bin/python tools/validation/corpus_check.py --self-test`
  Expected: exit `0`; each assertion is shown failing on a deliberately broken fixture,
  proving the guard can go red.
- Command: `.venv/bootstrap/bin/python scripts/validate_bootstrap.py`
  Expected: exit `0`, standalone `PASS`.
- Command: `git diff --check`
  Expected: exit `0`.
- Manual check: a second reviewer confirms each seeded contradiction is professionally
  plausible and that no seeded item was derived from observed model behavior.
  Expected: pass.
- Manual check: the protocol contains no leading question and no label outside the three
  fixed ones. Expected: pass.

## Integration contract

`P4-BHV-01` receives a corpus whose measurable documents are inside the PC-01 envelope
and whose ground truth is machine-verified, so a false negative is countable.
`P4-INT-01` receives a schema against which every session record validates.

## Failure/idempotency/security cases

- A document failing `corpus_check.py` is removed, never rescued by loosening the check.
- No customer or production payload enters Git under any provenance value.
- Re-running the checker changes no tracked file.
- Fewer than 12 surviving measurable documents is reported as `BLOCKED`, not shipped. The
  corpus floor and the G4 gate floor are the same number by design: if fewer than 12 reach
  a terminal state, the sample statement in the execution plan is recomputed at the
  surviving count before any rate is reported.
