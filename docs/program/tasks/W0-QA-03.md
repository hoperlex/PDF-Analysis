# Task W0-QA-03 — validator reads the canonical contract version key

> **Status: completed, independently accepted and integrated.**
> Integration commit: `23dddf99f833d12cd4cc22d11e224d4b278872bf`.
> `W0-DOM-02` may now remove the deprecated domain mirror.

## Outcome

Teach `scripts/validate_bootstrap.py` to require `contract_version` instead of the
bare `version` key on the domain error catalog, so the owner's canonical-key decision
can actually be completed. Until this lands, no contract family can drop its bare
`version` key without failing the very gate every wave task must pass.

## Problem

The repository owner fixed `contract_version` as the canonical machine-contract
version key and directed that the bare `version` and `schema_version` keys be removed
before freeze (`ID-01`, recorded in `docs/architecture/CP00_OWNER_DECISIONS.md`).

`_validate_error_catalog` in `scripts/validate_bootstrap.py` hard-requires
`("contract", "version")` on `contracts/domain/v1/error-codes.json`. The validator is
frozen by `W0-QA-02` and is outside every W0.2 lane's allowed paths, so the DOM lane
could not remove its bare `version` key: doing so fails `validate_bootstrap.py`, which
is a required gate of its own task. The DOM lane therefore kept `version` as a
declared deprecated compatibility mirror, pinned by the same `const` as
`contract_version` so the two cannot diverge, and recorded this removal gate.

This task is that gate. It is deliberately small and owns exactly one hotspot.

## Deliverables

1. `_validate_error_catalog` requires `("contract", "contract_version")` as non-empty
   strings. The bare `version` key is neither required nor forbidden while the
   deprecated mirror exists, so this change alone does not break the current tree.
2. A catalog carrying only the old `version` key and no `contract_version` is an
   accumulated, artifact-specific error naming the missing key — not a traceback and
   not silence.
3. Regression tests covering: catalog with `contract_version` only passes; catalog
   with both keys passes; catalog with `version` only fails naming `contract_version`;
   catalog with a non-string or empty `contract_version` fails. Every existing
   `W0-QA-02` regression continues to pass unchanged.
4. `scripts/README.md` records that the validator reads `contract_version`, and that
   the bare `version` key is accepted only as a transitional mirror scheduled for
   removal by the DOM owner.

  Expected: exit `0`; every pre-existing regression plus the four new cases pass.

  `d=$(mktemp -d) && printf "raise ImportError('simulated missing dependency')\n" > "$d/jsonschema.py" && PYTHONPATH="$d" .venv/bootstrap/bin/python scripts/validate_bootstrap.py; rc=$?; rm -rf "$d"; test $rc -ne 0`.
  Expected: exit `0` from the `test`, meaning the validator itself exited non-zero,

  interpreter lacking `jsonschema`. That form passes or fails by accident of whatever

  deterministic on any host and mirrors the seam the `W0-QA-02` regression suite
  already uses. Do not uninstall anything from a shared environment to test this.
- Command: `git diff --check -- scripts tests/contract`.
  Expected: exit `0` and no output.
- Command: `git diff --name-only 43a84d93fd544573226b82860ab24f924ed66d83 -- scripts tests`.
  Expected: only the three allowed paths are listed.

## Integration contract

After acceptance, callers may rely on exit `0` plus a standalone `PASS` meaning the
domain error catalog declares a non-empty string `contract_version`. Presence or
absence of the deprecated bare `version` key no longer affects the result. Unavailable
schema tooling or any failed check still yields non-zero and cannot be mistaken for
success. The script remains a read-only repository validator with no network or
external side effect.

## Follow-up this unblocks

Once accepted, the DOM owner removes the `version` mirror and its `deprecated_fields`
block from `contracts/domain/v1/error-codes.json` in a separate contract change, and
`W0-EVT-01` can then satisfy its repository-wide sweep asserting that no machine
contract still declares a bare `version` or `schema_version` envelope key.

## Failure/idempotency/security cases

- Missing or non-string `contract_version`: explicit non-zero, artifact-specific
  diagnostic, no `PASS`, no fallback.
- Both keys present and disagreeing: not this task's concern — the DOM schema pins
  them with the same `const`; the validator reads `contract_version` only.
- Repeated runs are read-only and idempotent: no cache, generated file, package
  installation or network call.
- Diagnostics must not print environment variables, credentials or file contents
  unrelated to the failing check.

## Rollback / feature flag

No feature flag applies: a validation gate must not have a bypass. Roll back by
reverting only the three allowed-path changes; no schema, migration, runtime state or
external side effect requires recovery.
