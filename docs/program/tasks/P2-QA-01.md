# Task P2-QA-01 — independent backend journey, restart and negative-path evidence

> **Status: specified; not dispatchable.** Planned as the P02 verification task. It tests
> modules and does not edit them.

## Outcome

One independently authored suite proves the whole PC-01 backend journey end to end,
including restart, replay determinism and every explicit failure, with no lane grading its
own work.

## Depends on

- none complete at plan time

Planned predecessors and dispatch condition — this task is not dispatchable until each
is accepted and integrated, and it must be authored by an agent that wrote none of the
modules under test:

  - `P2-API-01` — the frozen API surface
  - `P2-AI-01` — the recorded provider adapter

## Frozen inputs

- every P02 module public API and the frozen API contract, at their accepted commits
- the AR corpus and the recorded provider fixtures, read only
- `PROTOTYPE_PROFILE.md` §8 items 1 to 3, 5, 8, 9 and 10; items 4, 6 and 7 need the UI and
  belong to `P3-QA-01`
- migration head: the P02 head, read only
- base commit: the accepted integration commit carrying API and AI

## Allowed paths

- `tests/e2e/p02/**`, `tests/integration/p02_journey/**`
- `docs/program/reviews/P2-QA-01.md`
- `docs/program/tasks/P2-QA-01.md`
- `docs/navigation/entries/p2-qa-01.json`

## Forbidden hotspots

- all of `src/auditmanager/**`, `db/migrations/**`, `contracts/**`, `fixtures/**`, root
  locks and the `Makefile`
- `tests/integration/{db,storage,foundation}/**` and every lane-owned test directory
- CP-00 evidence and Git tags

## Non-goals

- No production-code fix: a defect is reported to its owner and never patched here.
- No UI, CSV or live-provider assertion in the automated suite, and no performance target.

## Deliverables

- one recorded-mode journey test: project, upload, run, `published`, both seeded
  contradictions and the placeholder present with correct pages and exact quotations,
  accept one, reject another, append a comment, and verify verdicts and history
- restart evidence: kill the process mid-run, restart, assert canonical state intact, the
  interrupted run explicitly failed rather than running, the abandoned command key returning
  `idempotency_key_stale`, and a fresh run under a new key reaching `published`
- duplicate-request evidence: identical upload, run and decision commands under identical
  keys producing no duplicate version, run, observation or decision
- negative-path evidence for every input fixture plus checksum mismatch, missing recording,
  ungrounded model item and a `partial` run
- a review report with commands, results and the grounded versus diagnostic counts, plus the
  exact manual live-run procedure and its acceptance criterion handed to P03 rather than
  asserted automatically

## Required tests

- Precondition: the dedicated serial integration instance, with no authoring lane using its
  instance name, ports, database or bucket concurrently.
- Command: `make foundation`
  Expected: exit `0`.
- Command: `.venv/bin/pytest tests/integration/p02_journey`
  Expected: exit `0`; the recorded journey publishes exactly the seeded issues and no
  control statement.
- Command: `.venv/bin/pytest tests/e2e/p02`
  Expected: exit `0`; restart, duplicate-request and every negative path behave as specified.
- Command: `git diff --check`
  Expected: exit `0`.

## Integration contract

This suite is the P02 exit evidence and the input to the PC-01 runbook. It asserts only
public seams; a test reaching into a module's internals is itself a defect.

## Failure/idempotency/security cases

- Every assertion is a path set or a state value, never a bare exit code of a lane's own
  script.
- The suite makes no network call and asserts no model wording.
- Cleanup is scoped to generated resources and leaves the checkout unchanged.

## Rollback / feature flag

Tests only. Revert the QA commit without touching product code.

P50 2 days, P80 4 days.

- the exact certified module commits and the fixture identity
- commands and results with measured elapsed time and the tree it was measured on
- the defect register and the manual live-run procedure for P03
