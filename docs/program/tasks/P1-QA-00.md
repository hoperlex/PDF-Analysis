# Task P1-QA-00 — verify the converged PostgreSQL/S3 foundation

> **Status: specified; dispatch after all three P01 providers are accepted and
> integrated.** This task tests providers and does not edit them.

## Outcome

One hermetic foundation suite proves clean bootstrap, migration, privacy, verified blob
publication, failure behavior and persistence across restart on the converged tree.

## Depends on

- `P1-INF-01` — completed and integrated
- `P1-DB-01` — completed and integrated
- `P1-STO-01` — completed and integrated

## Frozen inputs

- accepted FF-01 and `FOUNDATION_LOCK.json`
- provider public seams at their accepted commits
- migration head from `P1-DB-01`
- base commit: convergence commit supplied at dispatch

## Allowed paths

- cross-provider tests under `tests/integration/foundation/**`
- foundation section of `tests/integration/README.md`
- `docs/program/tasks/P1-QA-00.md` status/handoff

## Forbidden hotspots

- every provider, root lock/command, migration, contract, runtime composition and web
- CP-00 tests/evidence and Git refs

## Non-goals

- No provider remediation, product schema, API route or production hardening.

## Deliverables

- cross-provider positive and negative tests matching FF-01 section 7
- a restart/persistence test and anti-vacuity checks proving real PostgreSQL/MinIO usage
- concise test report with exact environment and provider commits

## Required tests

- Precondition: the integrator supplies one clean, dedicated acceptance instance and no
  provider authoring lane uses its instance name, ports, database or bucket concurrently.
- Command: `make foundation`
  Expected: exit `0` from a clean local state.
- Command: `make down && make up && make check-services && make check-db && make check-storage`
  Expected: exit `0` without loss of accepted test state.
- Command: `.venv/bootstrap/bin/python scripts/validate_bootstrap.py`
  Expected: exit `0`, `PASS`.
- Command: `git diff --check`
  Expected: exit `0`.

## Integration contract

The integrator may rely on one green foundation command covering the accepted providers.
QA acceptance certifies the provider commits, not QA's own unreviewed changes.

## Failure/idempotency/security cases

- Tests fail if SQLite/filesystem substitutes are used.
- Tests fail if anonymous bucket access succeeds or corrupt content becomes canonical.
- Cleanup is scoped to generated test resources and restores the checkout unchanged.

## Rollback / feature flag

Tests only. Revert the QA commit without changing provider data.

## Handoff

- exact certified provider commits
- commands/results and elapsed time
- any non-blocking platform limitations
