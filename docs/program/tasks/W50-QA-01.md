## Deliverables

- the brief of `W50-PLAN.md` §4 `W50-QA-01`, one test (or one recorded browser drive) per item:
  - keyboard paths through both primitives (`Disclosure`, `Menu`): Enter/Space open,
    ArrowUp/ArrowDown move, Home/End jump, Tab leaves and closes, through the primitives' exported
    logic in node and through the real frame in a browser
  - focus return to the trigger after Escape and after choosing an item
  - Escape closes each primitive
  - an outside click closes the menu (browser)
  - a guest is redirected from every registered `session` screen to `/login?next=<that concrete
    path and query>` — every row of the registry, dynamic segments filled with well-formed
    identifiers, driven against `requireScreen` and the real register
  - `admin` screens are absent from the menu for an expert — W50 registers no `admin` row, so
    this runs against a fixture registry with one, and a second test asserts the live registry's
    role-gated set (empty in W50, by `R-60`) so the fixture case is not mistaken for coverage of a
    live row
  - 780 × 900 has no horizontal overflow for every menu state: guest; signed in with groups in one
    row; stacked «Меню» open; account menu open; 66-character `displayLabel` with a 254-character
    e-mail; an incomplete-profile account whose label falls back to a long login (the contract
    allows `display_label` up to 254 characters) (browser, `scrollWidth <= innerWidth` per state)
  - the `/403` screen for every role-gated row names the role the registry requires — fixture
    registry plus the live set, as above
- `R-66`: the menu's groups and items equal the ruling's, in order; `/optimisation` is absent from
  every group, registered in `hidden`, and a complete-profile session opens it; each of the four
  stubs is registered `session`/`any`, renders `RoutePlaceholder`, shows no digit, says it is not
  implemented and invents no data; a guest is redirected from each stub with its `next`
- each test shown able to fail by one mutation of a copy of the subject (restored), output in the
  report; a QA test that cannot fail is removed by QA itself
- the report `docs/program/W50-QA-01.md` with the six items of `AGENTS.md` §5 and the findings
