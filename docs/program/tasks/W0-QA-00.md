# Task W0-QA-00 — fail-closed bootstrap schema validation

## Outcome

Make `scripts/validate_bootstrap.py` exit non-zero with an actionable diagnostic and
without printing `PASS` whenever `jsonschema` cannot be imported. Preserve the
existing successful full schema/example validation path when the dependency is
available, and prove both paths with deterministic focused tests.

This task is the explicit QA workstream named by the W0.1 stage prose but omitted
from the original S00 task table. It is semantically independent of `W0-BHV-01` and
therefore runs in parallel.

## Deliverables

- `scripts/validate_bootstrap.py`: explicit fail-closed dependency gate. On import
  failure it reports the dependency and remediation context, returns a non-zero exit
  status, and cannot reach the final `PASS`. With `jsonschema` available, every
  existing schema and shipped-example check still executes with the same or stricter
  failure semantics.
- `tests/contract/test_validate_bootstrap.py`: isolated deterministic tests that
  simulate missing `jsonschema` without mutating the shared interpreter installation,
  assert non-zero/no-`PASS`/actionable output, and exercise the available-dependency
  success/control path through a test seam or real dependency when present.
- `scripts/README.md`: document that `jsonschema` is a mandatory validator runtime
  prerequisite, the command's exit-code contract, and what missing-dependency output
  means. Do not prescribe an unowned root dependency change.

Any internal test seam must be private, deterministic and incapable of suppressing
the production dependency failure by default.

## Integration contract

Callers may rely on exit `0` plus `PASS` to mean schema machinery was available and
all existing bootstrap checks ran successfully. Any unavailable schema machinery or
validation problem yields non-zero and cannot be mistaken for success. Diagnostic
wording may evolve, but it must name the blocking dependency/check and remain
actionable. The script remains a read-only repository validator with no network or
external side effects.

## Failure/idempotency/security cases

- `ModuleNotFoundError`/`ImportError` for `jsonschema`: explicit non-zero blocked
  result, no `PASS`, no fallback parser and no silent notes-only mode.
- Unexpected exception while importing schema tooling: fail closed with sanitized
  context; do not expose environment secrets or a misleading success result.
- Invalid schema/example or existing repository invariant: preserve non-zero behavior
  and identify the failing artifact/check.
- Test simulation: must restore import/module/output state after each test so shared
  tests are order-independent and repeatable.
- Repeated validator runs are read-only and idempotent; no caches, generated files,
  package installation or network calls.
- Paths and diagnostics must not print environment variables, credentials or file
  contents unrelated to the validation failure.

## Rollback / feature flag

No feature flag applies: a validation gate must not have a bypass. Roll back by
reverting only the three allowed-path changes if they regress the normal validator
path. No schema, migration, runtime state or external side effect requires recovery.
