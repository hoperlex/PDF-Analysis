## Новый пользовательский путь

В свежем обычном `extended-review-v3` с ненулевым native/распознанным текстом добавлено отдельное извлечение структурированных параметров: тип объекта, этажность, площади, отметки/размеры, нагрузки/мощности, расходы, температуры/давления, оборудование, материалы и системы. Предметные подсказки берутся из сохранённых original-derived `project_params.md` по подтверждённому разделу; JSON-примеры исходных значений не передаются как данные проекта. При отсутствии специального исходного перечня это явно указывается модели. Общая схема доступна всем15 разделам.

Это **кандидаты параметров**, не утверждённый паспорт, нормативная проверка, канонические findings или экспертный акт. Значение и непустые unit/subject должны дословно встречаться в точной цитате реального переданного источника. Цитата проверяется внутри конкретного native/распознанного фрагмента; сохраняются физическая страница, артефакт, SHA исходного текста/фрагмента и диапазоны Unicode code points. Единицы не пересчитываются, разные значения не разрешаются моделью, повторы сохраняются.

## Стоимость, источники и восстановление

Новый независимый `project_parameters_policy` до начала резервирует до8 обращений по20000 символов / до24 кандидатов в ответе:8×100000 входных и8×8000 выходных токенов. Это глобальная граница на прогон. Свежий `AUDITMANAGER_PROJECT_PARAMETERS=0` исключает блок. Ранее принятые команды без поля не получают дополнительных обращений; для заведомо отсутствующего текста бюджет не резервируется.

Используются реальные подготовленные native-страницы и отдельные записи распознанного слоя. До20000 записей просматриваются попеременно из двух каналов, до1024 фрагментов /8000000 символов индексируются, одна исходная запись ограничена2000000 символов, хэширование исходных записей —32000000 символов. Выбор до8 фрагментов учитывает предметные слова, разнообразие страниц и16-страничных окон. Это ограниченный отбор, не обещание полного паспорта. Все известные счётчики, непопавшие фрагменты, причины и признаки сокращения списков примеров сохраняются; манифесты примеров ограничены128 записями.

`runs/project_parameters.py` использует переданный durable-call seam обычного Run: существующий журнал, exact request/reply custody, idempotency, денежный потолок, отмена и запрет нового расхода при неизвестном исходе. Сырые ответы сохраняются до разбора. Программное чтение/выгрузка и повторное использование готовой записи новых модельных вызовов не создают. Неопределённый эффект не повторяется скрыто. Частичный/ошибочный паспорт влияет на неполный итог, не удаляя прежние находки/наблюдения.

У параметров собственный hash фактического кода/зависимостей и section rules. Существующие coverage/core/workflow.py не менялись этим блоком: добавление отдельного параметрического bundle не заставляет команды без него переоценивать прежние B5-модельные запросы. Сохранённая форма политики читается независимо от текущего bundle; перед новым платным параметрическим действием runtime сверяет фактический bundle и при изменении требует новое согласие. Дополнительно ранняя ошибка основного v3 завершает ожидающие nested-результаты явным failed/skipped, сохраняя уже готовые записи.

## Интерфейс и выгрузки

Отдельная панель показывает фактические лимиты/охват/состояние, список с поиском/типами и страницами по25 кандидатов, все цитаты и исходные записи. Источник открывается через существующий защищённый PDF viewer; распознанные диапазоны не объявляются native/PDF-координатами. MD/HTML и полный JSON содержат параметры, происхождение, квитанции и пропуски. Технический XLSX добавляет `ProjectParameters` и lossless `ParameterReceipts`; фильтр интерфейса не отбрасывает данные выгрузки. Чтение и экспорт не вызывают модель.
