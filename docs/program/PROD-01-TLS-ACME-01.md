## 1. What was built

The three listeners of `R-146s` and who decides them:

| listener | where | serves | file | exists when |
|---|---|---|---|---|
| plain application | `127.0.0.1:${ALPHA_HTTP_PORT}` -> 8080 | the whole application | `compose.server.yml`, unchanged in effect | always |
| challenge | public `${ALPHA_PUBLIC_ADDRESS:-0.0.0.0}:${ALPHA_ACME_HTTP_PORT:-80}` -> 8081 | the ACME webroot and a `301` to HTTPS; **no `proxy_pass` or any directive that hands a request to another tier** | `infra/acme/compose.acme.yml` + `proxy/acme-challenge.conf` | `ALPHA_CERT_NAME` is set |
| application over TLS | public `...:${ALPHA_HTTPS_PORT:-443}` -> 8443 | the application with HSTS | `proxy/compose.tls.yml` (now **only** the port) | cleared (`ALPHA_PUBLISH_HTTPS=yes`, until `PROD-02`) **and** a pair exists |

- **ACME client** (`infra/acme/`): `Dockerfile` (Alpine pinned by the digest `infra/minio/Dockerfile` already pins; `certbot` installed by exact apk version from `client.pin`; unprivileged user; no socket), `entrypoint.sh` (validate, wait until the proxy serves the webroot, `certbot certonly --webroot --keep-until-expiring`, export, sleep 12 h; retries 1, 5, 15 minutes then hourly, never exits on a refusal), `export-pair.sh` (copies only the pair, atomically, key `0600`; **refuses to put a staging pair over a production one**), `check-served.sh` (asks `proxy:8443` what it serves: exit 10 nothing, 11 expiring, 12 untrusted, 13 wrong kind), `compose.acme.yml` (service, three named volumes: the account key on `acme-state` which the proxy never mounts, the pair on `certs` and the tokens on `acme-webroot`, both read-only on the proxy).
- **Proxy** (`infra/deploy/proxy/`): `acme-challenge.conf`; `watch-certificate.sh` (the timer of `ADR-0021`: every 60 s a changed pair makes it re-run the switch, run `nginx -t`, and reload; a pair nginx rejects is never applied and the TLS block is taken out again so a restart cannot load it; a failure with and without the block is not blamed on the pair); `enable-tls.sh` (messages only); `compose.tls.yml` (rewritten, 443 only).
- **Decision** (`infra/deploy/lib/proxy-listeners.sh`): `listeners_name_problem`, `listeners_overlay_files`, `listeners_https_verdict`, pure functions of three words. `PROD-02` replaces the computation of `https_wanted` and nothing else.
- **`deploy.sh`**: five guards (`acme-files-present`, `acme-settings-well-formed`, `acme-client-pinned`, `public-ports-free`, `acme-pair-answerable`); the compose files became a list whose first and, with no name, only member is `compose.server.yml`; the decision is taken after the build and before `up`; `acme` joins the long-running services and the images that must exist.
- **`verify-deployed.sh`**: with a name, a section 4 runs `check-served.sh` in a one-off acme container (the host promises no `openssl`); exit **7** for a certificate that is missing, staging, untrusted or within 14 days; exit 4 if the question could not be asked; a stack set to the test endpoint fails unless `--acme-rehearsal` is given (the default of `ALPHA_ACME_STAGING` is `yes`, so a host that lost the line is caught here).
- **`readiness.sh`**: `tls` asks what the proxy serves (same script, reported not enforced); `plain-http` asks the challenge listener whether it redirects and reaches no application route. `--tls-dir` is gone (nothing is a directory any more).
- **HSTS and `Secure`**: `tls-server.conf` is unchanged (HSTS `max-age=31536000`, no `includeSubDomains`, no `preload`; `X-Forwarded-Proto $scheme` = `https` on an `ssl` listener, which `requestIsSecure` in `web/src/app/bff/session/store.ts` reads). Tests pin each link.
- **Docs/config**: `alpha.env.example` (the certificate name is a deploy variable, placeholder `host.example.invalid`, commented out; the live name is nowhere), runbook section 6 rewritten (plus sections 1, 5, 8, 9 and the host-nginx note), `infra/deploy/README.md`, header of `deploy.sh`, comments of `compose.server.yml`.

## 8. Limits and risks (the integrator decides what to relay to the owner)

1. **The client version is unresolved.** `infra/acme/client.pin` says `UNRESOLVED`; `deploy.sh` refuses a host with a name set (`acme-client-pinned`) and the image build refuses too. Resolving it is one `apk policy` call with a network (runbook section 6, step 1; the output's shape is not observed). The packages `certbot` depends on float within Alpine 3.22 at build time: the image is identified by its base digest and this version, not by a lock. The brief asked for a digest-pinned image; a digest for an ACME client could not be obtained offline and none was invented.
2. **The other application on the host.** `EXPOSURE-REVIEW-01.md` `E-6`: the host's nginx also serves a different application. Stopping it for the cutover (runbook step 4) takes that application down too; this stack cannot share ports 80 and 443 with another terminator. Runbook step 2 says so and stops the procedure there. This needs the owner's attention before any date is set.
3. **Nothing ran.** No authority, no image build, no container, no `docker compose config` merge. Compose's merge of the overlays (lists of ports and volumes appended, `depends_on` added) is expected behaviour and was not observed; the PyYAML parse is of each file alone. The first run is the owner's staging rehearsal.
4. **`ALPHA_PUBLISH_HTTPS` is the interim gate.** An operator who sets it `yes` before changing the seeded password opens 443 on the published pair. `PROD-02` replaces the computation by the default-credential check. **Until then `reset.sh --restore` and `copy-serve.sh restore-db` do not touch the listeners** (the lane left both files unchanged on purpose).
5. **Rate limits.** `R-146ac`: a name under `sslip.io` shares the authority's limits with its zone. The default `ALPHA_ACME_STAGING=yes` and the rehearsal first are the mitigation; the entrypoint's retry schedule (1, 5, 15 minutes, then hourly) stays under the five-failures-per-hour limit.
6. **A failed renewal alerts nobody** (`R-146k`). It is found when someone runs `verify-deployed.sh` (exit 7 `EXPIRING` below 14 days; renewal starts at 30).
7. **Rollback leaves the `acme` container running** (compose treats it as an orphan once the name is emptied). The runbook gives the removing command; `deploy.sh` does not run it.
8. **Two stale hint lines in `infra/deploy/reload-proxy.sh`** (a comment and the error text, "add proxy/compose.tls.yml if TLS is on") name the old layout. The file was not in the lane's allowed paths and was not touched; a following `infra/**` lane (`PROD-02`/`03`) should reword them. Its logic is unaffected: the proxy's bind mounts are all under `proxy/` and the new volumes are named volumes. Its throwaway `nginx -t` container gets only the bind mounts, so it tests the configuration **without** the TLS block (the `certs` volume is absent there).
9. **`enable-tls.sh` still loads a pair it was not shown to be loadable at container start** (the watcher validates on change; a restart during the milliseconds between the key rename and the chain rename of a renewal could see a mismatched pair). The window is tiny and was left as the ADR designed it.
10. **Webroot permissions in the image are unverified** (section 4).
11. **Five `deploy.sh` guards = more refusals on a host that sets a name.** None is reachable without a name.
