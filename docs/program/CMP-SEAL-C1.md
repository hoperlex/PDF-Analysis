**Shape decisions the ADR left to this seal.**

1. *The revision of the effective matrix is a pair*, `{matrix_id, edit_no}`: the algorithmic build it rests on (`cmx_`) and the number of manual edit events of the document set (a gapless number, as in `0035`). An edit batch and an undo carry the pair they started from; either part moving is `409 conflict` (`comparison_matrix_stale`). An accepted AI link binds `matrix_id` (ADR decision 14), a manual edit binds the version-order revision (`order_id`, empty for the document's own order).
2. *A page is a version and a coordinate in it* (`ComparisonPageRef`), never a display number: the pages of an edit exist before any page profile does (the migrated `0035` approvals name `(version, page number)` only). A row of the matrix is identified by the profile identity (`cpr_`) of its first page and is valid within one revision.
3. *The sheet pair of a transition has its own identity* (`ctp_`) and points at the content-keyed result (`csp_`, decision 15): two sheets of equal content in one transition share one result, the permit reconciliation and parts coverage depend on the transition and are records of the pair, and the result stays immutable.
4. *The verdict of a transition is a list of codes* (`incomplete`, `content_same`, `zones_only`, `different`, `composition_changed`, `needs_review`, `calculation_failed`) beside the counts of `summary`; the Russian sentence of the inventory (§4.2) is the client's.
5. *Open vocabularies are string patterns, closed ones are enums*: the statuses, channels, confidences, flags, layers, permit states and step states are enums; the region class of a difference, a text-change kind, a service-note kind and the forcing reasons (`^[A-Z][A-Z0-9_]{2,63}$`) are pattern-typed strings so that `CMP-ENGINE-01` is not blocked on a vocabulary it has not finished.
6. *The tile's layers are one query value*, `layers=main,noise` (a pattern over the eight layer names), because the generated client carries a query value as a scalar and an array parameter broke its type (`tsc` found it; `ComparisonLayer` stays the enum of a difference's layer).
7. *Preparation covers «Повторить» and «Подготовить»*: `prepareComparisonMatrix` queues the missing or failed page profiles of the document set and then the build; there is no separate profile-retry operation.
8. *«Досчитать» is `finishComparisonSeries`*, distinct from `resumeComparisonSeries` (which continues a paused series); «Заново» is `startComparisonSeries` with `restart: true`, a new series that names the one it replaced.

**New refusals, all registered reasons under existing codes** (no new error code): `conflict`: `comparison_matrix_stale`, `comparison_edit_none`, `comparison_series_active`, `comparison_series_state`, and `comparison_version_order_stale` also on `startComparisonSeries`; `validation_failed`: `comparison_edit_invalid`, `comparison_edits_limit`; `dependency_unavailable`: the four dependency class names and `comparison_versions_module`.

With the module off nothing changes. The guard is one condition in `bootstrap/adapters.py` fed from the composition root's parsed module set; it is shown failing by a mutation (§9).

**The upload flag (CMP-INGEST-02 finding).** `CreateComparisonUploadRequest.compare_after_preparation` and the column `comparison_upload.compare_after_preparation` (`NOT NULL DEFAULT false`, frozen) exist. The wired create path is `ingest/comparison_pdf` and is outside this seal, so `ComparisonUploadAdapter.create_upload` refuses `true` with `503 dependency_unavailable` (`comparison_series`) before anything is created, and accepts absent or `false`; `CMP-SERIES-01` stores the flag and removes the refusal. A flag that was accepted and ignored would be a silent fallback.

## 8. Limits, risks, what the seal does not do

* Every stub answers `503` for any request that passes authentication, the role and the request's own shape; the module flag gates only the three `0035` operations. The worker kinds and the queue items of the lanes do not exist yet.
* The shapes of the engine's result (`ComparisonSheetPair` members after `canvas`, region classes, text-change kinds, service-note kinds) follow the original's inventory (§4.1) and plan §1.1; `parts.py`, `permit.py`, `blocks.py` and `block_alignment.py` of the original were not read (`ORIGINAL-UNREAD-SOURCES.md`), so `ComparisonPartsCoverage` and `ComparisonPermit` are `[own design]`. A lane that needs another member STOPs to the FIX slot.
* The matrix rows are stored as `jsonb` (`comparison_matrix.rows`) and the result detail as `jsonb` (`comparison_sheet_pair_result.result`): the lanes may change their internal form without a migration; the API shapes are fixed.
* `comparison_matrix_edit` is written by migration `0039` alone until `CMP-MATRIX-01` lands. A migrated edit binds no version-order revision (`order_id` empty): it was made against the document's own order.
* `compare_after_preparation` is refused when `true` (see §3) until `CMP-SERIES-01` stores it; that lane needs a grant for `src/auditmanager/ingest/comparison_pdf/**` or `comparison_batch/**` to write the column, and for `src/auditmanager/comparison/work/**` to add the series filter next to `comparison_upload_id`.
* The `comparison_work.comparison_series_id` column exists; `comparison/work/**` does not use it yet.
* `getComparisonQueueSummary` returns an object, not a page; when `CMP-VC-OVERVIEW-01` serves it, it joins the aggregate operations of `test_an_absent_parent_is_not_an_empty_page.py`.
* Not built: a Russian sentence in `catalog-message.ts` for the new reasons (`comparison_matrix_stale`, `comparison_series_active`, ...); they are the screens' words (`CMP-VC-UI-01`).
* The complete `make gate` was not run (`R-135`). The seal touches `contracts/**`, `db/migrations/**`, `infra/deploy/proxy/*`, `apply-grants.sh` and `web/FRONTEND_LOCK.json`, so `AGENTS.md` §8 case 3 asks one full gate on this lane, which `R-135` defers to the gate before the beta.
