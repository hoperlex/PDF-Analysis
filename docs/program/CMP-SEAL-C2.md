**Shape decisions the ADR and the task left to this seal.**

1. *One consented job, four methods* `[own design]`. `ComparisonAiJob` is the one object of every AI start (`pair_check`, `sheet_changes`, `spec`, `report`; each is also an executor work kind `comparison_<method>`). It carries the estimate it consented to, the state, the pause reason, the counts and the spend. Controls are addressed by the job's identity under a path of the method (`/comparison-ai-pair-checks/{id}/pause`, `/comparison-ai-sheet-jobs/{id}/pause`), reads by the scope (document set, series, sheet pair, transition), so each lane owns its own paths and its own dependency class.
2. *Estimate, then a start that carries it* (`Q-CMP-7`, decision 19). `ComparisonAiEstimate` (questions, pairs, sheets, transitions, versions, calls, images, image bytes, prompt characters, tokens, the routed model with its revision and billing, `estimate_micros`, `ceiling_micros`, `blocked_by`) has an `estimate_digest` that binds the route, the pinned model, the ceilings and every figure. A start carries `ComparisonAiConsent {estimate_digest, confirmed}`; a stale digest is `409 conflict` `comparison_estimate_stale`, a missing or false consent `422 validation_failed` `comparison_consent_required`. Money is integer micro-USD, as in the spend journal. The ceilings are refusals (`comparison_ceiling_job`, `comparison_ceiling_day`, both `409 conflict`), the 1.2 x overrun is the pause reason `overrun` (a resume then carries a new consent), a connection that is not metered has `estimate_micros` 0 and no ceiling.
3. *A report is made in two steps*, so an estimate always precedes a spend: `createComparisonReport` or `uploadComparisonReportSource` (a raw `text/markdown` body, at most 20 MiB, the original's limit) make a `draft` with its estimate and call no model; `startComparisonReport` consents. «Подготовить отчёт для заказчика» makes a client draft from an analytic report. «Пересобрать PDF» is its own command and calls no model. «Удалить» is a tombstone (`deleted_at`): no published blob is deleted (decision 9).
4. *The AI pair check writes no client-visible link.* Accepted answers become `comparison_ai_link` rows by the lane's rule; `listComparisonAiPairHints` reads the questions with their decision (`link_accepted` or one of the `hint_*` values, `none`, `answer_mismatch`, `failed`, `medium_*`), the hinted page and the stale flag. The matrix cell is not extended, so the matrix lane's code is untouched: a client joins the hints to cells by `(version_uid, page)`.
5. *The queue is per project* `[own design]`. The original's global stage queue is split in two: the launch queue («Очередь запуска») is a project's, and «Очередь «ИИ-описание изменений»» is the installation's read of the AI jobs that wait (`getComparisonAiQueue`). An AI step carries its own consent per set when its estimate exists, otherwise the entry waits and becomes `needs_consent`.
6. *Enum values are compounds.* The rendered-language guard learns bare Latin words from contract values, and `review`, `accepted`, `mismatch`, `text`, `image`, `preparation` and `analysis` are words it holds the owner ruled translated, so the values are `no_pair` and `medium_pair`, `link_accepted`, `answer_mismatch`, `from_text` and `from_image`, `preparing` and `comparing`, `transition_analysis`, `to_check`. The position field of a specification change is an open word (a pattern), not an enum. `CMP-VC-UI-02` registers the new enums in `TRANSLATED_SCHEMAS` when it renders them.
7. *Deterministic part A* of the specification is read per page profile and per sheet pair; the comparison table keeps a `positions` row per transition for a lane that stores it. `[own design]`: the original's `spec.py` is read (`ORIGINAL-UNREAD-SOURCES.md` §2.1) but its page output beyond the signature is not.

**New refusals, all registered reasons under existing codes** (no new error code): `conflict`: `comparison_estimate_stale`, `comparison_ceiling_job`, `comparison_ceiling_day`, `comparison_ai_job_active`, `comparison_ai_job_state`, `comparison_ai_nothing_to_do`, `comparison_description_missing`, `comparison_summary_unavailable`, `comparison_report_state`, `comparison_launch_entry_active`, `comparison_launch_entry_state`, `comparison_launch_queue_state`, and `comparison_matrix_stale` also on `startComparisonSeries`; `validation_failed`: `comparison_consent_required`, `comparison_step_not_queueable`, `comparison_report_source_invalid`, and `comparison_versions_few` on `startComparisonSeries`; `dependency_unavailable`: the five class names and `comparison_modules` (already registered), and `executor_route_missing` for a work kind with no route.

**Identity prefixes** (the catalogue goes 63 to 74; each fits `^[a-z][a-z0-9]{1,7}$`, none collides): `cai` AI job, `cpa` pair-check answer, `cpq` question, `csi` sheet item, `csd` sheet description, `cse` specification extraction, `cscp` specification comparison, `crt` report, `crpt` report part, `cra` report file, `cle` launch entry. ## 8. Limits, risks, what the seal does not do

* Every stub answers `503` for any request that passes authentication, the role and the request's own shape. The module-flag refusal is the one condition beside the stubs: while `ProductVersion.comparison_modules` does not include `versions` all fifty operations name `comparison_modules` (it is the first statement of every stub method, so it precedes any read, write or model call); once a lane wires an operation it must keep calling `_require_versions_module` first.
* Shapes marked `[own design]` in section 3 (the estimate and consent objects, the job object, the hint list, the per-project launch queue, the two-step report, the specification change and position shapes) follow the inventory where it fixes a behaviour and are mine where it does not. `spec.py` of the original is read only to the signature (`ORIGINAL-UNREAD-SOURCES.md` §2.1) and the original's page output of part A is not known, so `ComparisonSpecPositions` is the likeliest to need a field: a lane that needs one STOPs to the FIX slot and does not edit the contract.
* `estimate_digest` is specified (it binds the route, the pinned model revision, the ceilings and every figure of the estimate) and not computed; the AIPAIR lane owns the function, and the other four lanes call it, so the first lane to merge defines it (lane order in section 9).
* The spend of a job is read from the journal through `comparison_work.comparison_ai_job_id`; no `comparison_work` item of a `comparison_*` kind exists yet, and the worker side (a kind registered in `comparison/work/**`, a handler, the route lookup for the four new work kinds) is the lanes' work. The executor route only accepts the four kinds today.
* `comparison_ai_link` (table of `0039`) is written by the AIPAIR lane (accepted answers); until then it stays in `SEALED_NOT_YET_WRITTEN`, where `CMP-SEAL-C1` put it.
* The accepted pair-check answer is not a matrix-cell field: a client joins `listComparisonAiPairHints` to cells by `(version_uid, page)` (section 3, decision 4). If `CMP-VC-UI-02` finds that join too costly it asks the FIX slot for an additive cell field; no migration is needed for it.
* The queue read `getComparisonAiQueue` is the installation's and tagged `execution`; the launch queue is a project's. The original's single global stage queue is therefore two surfaces; the owner has not ruled on that split, it is `[own design]` and marked so in the contract descriptions.
* `D-263` registry part: skipped (section 3). Row `D-263` of `DEBT_REGISTER.md` stays open; this seal does not edit the register.
* The container directories were run once, on the final tree, not on a probe first (section 2).
* The complete `make gate` was not run (`R-135`). The seal touches `contracts/**`, `db/migrations/**`, `infra/deploy/proxy/*`, `apply-grants.sh` and `web/FRONTEND_LOCK.json`, so `AGENTS.md` §8 case 3 asks one full gate on this lane, which `R-135` defers to the gate before the beta.
* Two fix lanes (`CMP-C1-FIX-A`, `CMP-C1-FIX-B`) ran beside this seal from the same base. The seal's edits to `bootstrap/composition.py`, `bootstrap/adapters.py`, the stub registers and the rendered-language guard are additive hunks at the end of lists and files; a textual conflict there is resolved by keeping both sides.
* Commit trailers: the commits up to `bc313b9f` end with `Claude Sonnet 4.6`, the later ones with `Claude Sonnet 5.5` (the attribution line the harness gave from that point). The content is the same lane.
