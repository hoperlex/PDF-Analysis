# Двенадцатый блок: исходный нормативный контекст

База `origin/dev=8f5c9c45bc86cb8cca66e66ed9058df4afc98e66`, API1.14.0/migration0044. Task `BLOCK12-INT-1030`, root единственный автор, публикация dev /owner deploys.

В прежней batched сверке модель получала только поисковые выдержки. При разных запросах к одному нормативному абзацу общая registry также подменяла цитату отдельных наблюдений первой найденной выдержкой. Свежая независимая `norm_paragraph_context_policy` сохраняет собственные candidate quotes каждого input_id и добавляет настоящий текст того же абзаца с соседним контекстом из нашего корпуса. История без новой политики сохраняет прежние запросы и canonicalization.

Новый внутренний public seam `norms.read_norm_paragraph_context` проверяет квалифицированный snapshot и точные document/paragraph IDs, читает только надёжный исходный абзац, до6000 его символов и по1000 символов двух ближайших соседних абзацев. Если основной абзац помещается, передаётся целиком; иначе окно располагается вокруг дословной поисковой цитаты либо с начала при её отсутствии. Все фрагменты имеют реальный paragraph ID, ordinal/page/block, Unicode-диапазон внутри абзаца, полный известный размер, excerpt SHA256 и текстовую надёжность. Соседи с неподтверждённой надёжностью явно помечены. Дословное наличие исходной поисковой цитаты устанавливается отдельно; дата корпуса не становится доказательством актуальности.

На нормативный запрос отбирается не более12 контекстов candidate quote в пределах18000 символов кодированного JSON-контекста. Остальные, недоступные или не поместившиеся контексты имеют явные причины/счётчики; исходные наблюдения не исчезают. Отличающиеся выдержки одного абзаца разных наблюдений сохраняются в `norm_context_by_input`, без общей подменяющей цитаты. Декоратор не расширяет citation allowlist: модель по-прежнему может цитировать только первоначальный paragraph_id и дословную candidate quote своего input_id, не соседние или более длинные абзацы. Непереданный контекст или несовпадение цитаты отмечают процедуру частичной; это не полный нормативный движок раздела.

Политика связывает фактические application/reader hashes и проверяется до нового раннего платного действия. До согласия добавляется резерв100000 входных токенов на каждый уже запланированный local/global norm request. Новых model calls, выходных квот и canonical/expert записей нет. `AUDITMANAGER_NORM_PARAGRAPH_CONTEXT=0` исключает новый контекст и резерв только для свежих запусков. В режиме статистики сохраняется явно принятая owner uncapped authority; этот блок её не отменяет и не расширяет глобальные лимиты.

Запрос, наличие сохранённого ответа, replay и точные IDs/hash записываются раздельно. UI показывает страницы по10 квитанций, настоящий текст/сокращения и ссылку на документ корпуса. MD/HTML/JSON сохраняют все квитанции; новый лист технического XLSX `NormativeContext` содержит полные JSON-части без превышения предела ячейки. Фильтр интерфейса не сокращает выгрузку. Сохранённые ответы используют прежние request/source/unknown-effect guards; нормативный контекст не подтверждает, что модель верно применила каждый фрагмент.

Внутренняя public функция новая; transport/API/contracts/generated, migration0044, frozen analysis builders/coverage/workflow/project-parameter modules, routers/composition root, dependencies/locks, global styles, tests/fixtures и синтетика не затронуты. Только normal clean dev publication/read-back; деплой выполняет владелец.
