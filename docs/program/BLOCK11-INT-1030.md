# Одиннадцатый блок: соответствие находок повторных прогонов

База `origin/dev=82b472ddf9a21225b3e62e379ab0f89cd7d0f17d`, API1.14.0/migration0044. Task `BLOCK11-INT-1030`, root единственный автор, dev /owner deploys.

По исходникам публикации finding_uid создаётся заново для каждого прогона. Прежний B5 matcher по одному UID поэтому не мог сопоставлять одинаковые канонические находки разных прогонов. Аллокация принадлежит текущему прогону; оснований ослаблять проверку run_id нет.

Read-only сопоставление сохраняет приоритет общего UID, а для разных ID требует точного совпадения категории, текста, рекомендации, required/stated values и полного набора цитат/физических страниц/Unicode-диапазонов/блоков всех исходных и объединённых наблюдений. Непустые цитаты должны соответствовать длине диапазона; все наблюдения принадлежат запрошенному прогону. Неполная или неподтверждённая привязка не участвует в content matching. Порядок evidence/canonical selection не создаёт ложной разницы при равном полном наборе; кратность повторов сохраняется один к одному. Выделенные пары общего UID резервируются до content matching.

Новая связь — только соответствие для просмотра. Оба finding_uid, все записи/объединённые наблюдения и обе экспертные истории остаются раздельными. Изменение сохранённых нормативных оценок/предложенной критичности считается различием разбора. Текущий вердикт и экспертная критичность сравниваются отдельно; фильтр различий учитывает их даже при совпавшем анализе. Это текущая проекция момента чтения, не восстановление состояния на дату запуска.

UI показывает основание соответствия, исходные ID и обе стороны; страницы включают объединённые наблюдения. Полные JSON/HTML и CSV содержат основание и отдельный экспертный признак; JSON format повышен до saved-run-result-comparison/2. Все полученные материалы сохраняются независимо от фильтра; прежние64МиБ/полное чтение/отмена остаются. Модельные запросы, перенос решений и записи в БД не добавлены.

Изменены только четыре файла существующего stage-comparison widget (reader/model/report/UI) и программные документы. Contracts/API/generated, canonical publication, migration0044, routers/composition root, dependencies/locks, global styles, tests/fixtures и синтетика не затронуты. Интеграция — обычный clean dev push/read-back с сохранением входящих owner-коммитов; деплой выполняет владелец.

**UNVERIFIED:** никакие tests/build/compile/import/typecheck/lint/browser/DB/model проверки не запускались. Приёмка полного чтения, канонических/объединённых цитат, повторов, Unicode offsets, отсутствующих привязок, экспертных состояний, отмены и экспортов перенесена в D-290. Семантически близкие, иначе сгруппированные или иначе привязанные находки могут остаться отдельными; это не доказательство устранения замечания в документе.
