# W48 judges — attack the instruments, then the alpha boundary

These are candidate briefs. `W48-FREEZE-01` must replace the symbolic subjects with exact SHAs
before dispatch. Every judge owns one report, repairs nothing, restores every probe and records
the final diff as report-only.

## `W48-JUDGE-A` — Stage A false-green judge

**Subject:** accepted merge of `W48-PROSE` + `W48-GUARDS`, with `W48-AUDIT` read separately.
**Allowed path:** `docs/program/reviews/W48-JUDGE-A.md`.

Start from mutations, not the authors' reports:

1. Put a stale surface count behind each missed synonym and in each newly scanned file type.
2. Insert an early valid-looking historical heading before a stale live claim.
3. Change each independent error-count/migration/surface pin without updating its registry.
4. Weaken one migration constraint in a full-tree copy and prove a freshly migrated database,
   not an already-migrated lane database, observes it.
5. Swap two section, verdict and run-state rows whose counts are pairwise distinct.
6. Comment out an invalidation call, then put the same call text into a comment. The first must
   fail and the second must not pass.
7. Find one path/extension/noun the new scanners still discover only because their authors listed
   it explicitly.

For `W48-AUDIT`, independently select one bounded context the audit called clean and run a scope
query the auditor did not use. A missing scope is a finding even if no defect is found there.

## `W48-JUDGE-X` — black-box and attacker entry point

**Allowed path:** `docs/program/reviews/W48-JUDGE-X.md`.

Read the diff only after the black-box pass, then mutate each new guard independently.

## `W48-JUDGE-Y` — architecture and data-integrity entry point

**Subject:** the same merged Stage B SHA as X.
**Allowed path:** `docs/program/reviews/W48-JUDGE-Y.md`.

Begin from repository topology, not UI behaviour:

- trace every new/changed port through all implementations and prove routers still contain no
  SQL/storage/business logic;
- verify existence reads do not hydrate evidence, decisions, stages or model costs;
- compare the shared screen harness against every screen-wide consumer and enumerate deliberate
  focused exceptions;
- inspect DB + object-store mutations for dual-write/reconciliation and idempotency regressions;
- audit the command surface so `make gate` cannot see credentials/network and alpha acceptance
  cannot silently skip external phases;
- reconcile every closed debt row against executable evidence and every historical correction
  against the addendum rather than rewritten history;
- verify dependency/lock/composition/contract/migration bytes remain frozen.

## Cross-examination

X and Y exchange reports before any repair. For each finding the other judge records:

- **upheld**, **narrowed** or **falsified**;
- one new measurement or counterexample;
- whether both methods share an assumption with the subject;
- the smallest safe path grant for a repair.

Agreement without a different measurement is not independent evidence. Only the integrator opens
`W48-FIX`, and only for upheld release-blocking findings.

## Required report shape

Each report contains exact subject SHA, environment, commands with exit status, findings with
path/line/consequence/reproduction, mutation results, untested questions, final verdict and
`git diff --name-only <subject>..HEAD`. Credentials, cookies, provider bodies and customer data
are forbidden evidence.
