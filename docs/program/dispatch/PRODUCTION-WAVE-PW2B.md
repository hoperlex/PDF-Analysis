### Section lane template — `SECTION-<CODE>-FULL-01` (`R-146ag`, `R-146ah`, `R-146ai`; `A-7`)

Branch `agent/section-<code>-full-01`, worktree `.local/worktrees/section-<code>-full-01`. One lane per section code in the order above.
Result: the section's record in `docs/program/W59-SECTION-PROFILES-01.md` has every «open question for the expert reviewer» answered by a **written decision**, the cross-section decisions below applied, the section's recording rebuilt if its prompt changed, and its line of the expectations file says `reviewed`. **Nobody reviews the section afterwards** (`A-7`): so the decisions must be conservative and every one must be traceable.
Decision vocabulary (each open question gets exactly one): **K — keep** the v1 behaviour (state why no change is justified); **N — narrow** the prompt (add wording that removes a stated false-positive source; never widen); **X — exclude** an item (drop a checklist-derived bullet that the record shows cannot be a same-document cross-check). **Forbidden:** widening what a finding is, a new finding category (that is a contract change), any normative number, norm reference, threshold or class designation that is not in the section's own hash-pinned legacy source, any claim that an expert verified anything.
Cross-section questions (the four of the record, decided once for every lane): (1) site and contractor phrases («уточнить по месту» and similar) — **K**: they stay explicit placeholders under v1's wording, because turning them into accepted instructions is an expert's call and would silence findings; (2) «Итого» against the sum of rows — **K**: recomputation stays excluded; (3) text read from sheets — **K** unless the section's own record names a systematic false-positive bullet, then **N** for that bullet only; (4) missing items — **K**: no third kind of observation (it would be a contract change). A lane that disagrees reports it and still applies the table.
Premise to capture: the package (`profile.json`, `system_prompt.md`; for `PB` also `open_questions.md`), the section's record, the cross-section questions, `SECTION-RECORDINGS-01.md` and `fixtures/recorded/sections/README.md` (how a recording is rebuilt with `build_fixtures.py`; editing a prompt orphans its recording), the legacy source if it is on the host (`/root/projects/PDF-proverka`, hash-pinned; never write to it), how `status` and `profile_version` enter the identity and the recording hashes, and `tests/unit/analysis/text_profiles/section_profile_expectations.json`.
Steps: answer each open question (table in the report: question, K/N/X, reason, the exact change); edit `system_prompt.md` only where N or X; bump `profile_version` only if the prompt text changed (the expectations file and the pin tests decide what is consistent); set `status` to `reviewed` in `profile.json` and in your one line of the expectations file; rebuild `fixtures/recorded/sections/<code>/**` if the prompt changed; run the section's tests. `PB`: its `open_questions.md` is pinned by a test (at least eight numbered questions and `D-178`); append the decisions under the questions rather than deleting them, and keep the tests green; `PB` has no legacy source, so every decision that would need one is **K** or stays open and is listed (then the lane leaves `PB` at `draft` and says why).
Allowed paths: `src/auditmanager/analysis/text/profiles/<code>/**`, `fixtures/recorded/sections/<code>/**`, your one line of `tests/unit/analysis/text_profiles/section_profile_expectations.json`, `docs/program/tasks/SECTION-<CODE>-FULL-01.md`, `docs/program/SECTION-<CODE>-FULL-01.md`. Forbidden: every other section's files, `W59-SECTION-PROFILES-01.md`, the registry, `P02_LOCK.json`, `contracts/**`, migrations, the web, `infra/**`.
Tests: `tests/unit/analysis/test_text_profile_registry.py`, `tests/unit/analysis/text_profiles`, `tests/integration/sections/test_section_recordings.py`, `tests/contract/analysis_packages`; with the lane stack `tests/integration/composition/test_analysis_profiles_over_http.py`; web: `ln -s /root/projects/PDF-Analysis/.local/worktrees/gate-night/web/node_modules web/node_modules` then `npx vitest run tests/unit/analysis-settings` (reads the expectations file). Mutation proof: revert the status in `profile.json` only → the pin test goes red; revert your line only → red.
