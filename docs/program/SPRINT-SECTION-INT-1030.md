## Ограничения и исполнение

Свежая оценка стоимости закрепляет раздел, модель/тариф/соединение, общий SHA реализации и рубрик, все принятые источники в пределах загрузчика: до1000 визуальных источников и500 страниц PDF. Число окон — максимум из визуального и текстового объёма, не более63; до16 изображений на окно, до8 на вызов. Редкие IMAGE-блоки не обрезают остальные текстовые окна. Основные текстовые вызовы учитываются отдельно. На окно разрешается максимум6 дополнительных вызовов: два визуальных, комплексный, нормативный, критик, корректор. При отсутствии целей лишний вызов не выполняется.

Сохранённые ответы и native PNG используются повторно. Неопределённый оплаченный эффект останавливает новые вызовы. Для свежего v3 основная текстовая обработка использует существующее долговременное хранение ответов даже при единственном окне. Скрытые повторы Anthropic SDK отключены; право на явный повтор остаётся в существующем механизме журнала.

Обычный image-only PDF допускается в визуальный маршрут. OCR этим не появляется: native-цитаты, координаты и текстовые находки не выдумываются. Пустой native-набор проходит обычный grounding и выбор итогового состояния. Предварительные визуальные замечания не становятся автоматически каноническими экспертными находками.

Охват, усечение контекста, необработанные страницы/блоки, недоступные нормы и наблюдения вне окна критика сохраняются явно. Геометрические отказы portal, ограничения размера растров, ошибки исполнителя и недостаточный согласованный бюджет могут дать частичный результат. Полное равенство качества оригиналу и нормативная правильность не установлены.

## Сценарий для презентации

Это инструкция оператору, **не выполненный прогон**. Синтетику предоставляет другая сессия.

1. На стенде, куда владелец доставит этот кандидат, открыть проект и загрузить подготовленный комплект существующим ZIP/PDF-путём. Для обычного native PDF портал не обязателен. Подтвердить нужный раздел и стадию.
2. Выбрать настроенного исполнителя и начать **новый** обычный анализ раздела. Прочитать свежую оценку и согласовать достаточный конечный лимит. Уже принятый старый запуск не расширяет свой план.
3. На странице Run открыть «Расширенный анализ»: сначала сохраняется визуальный проход, затем выполняется основной текстовый анализ и оставшиеся процедуры. Ожидание первичного текста показано отдельно от завершения окна.
4. Показать источники, охват, нормативный статус, рекомендацию критика и исходный/исправленный кандидат. Для скана отсутствие native-текста объясняется явно.
5. Скачать технический XLSX либо MD/HTML/JSON. Это предварительная техническая выгрузка; стандартный экспертный XLSX остаётся отдельным действием. Экспертное решение принимается в существующем рабочем процессе.

Без настройки среды свежий план по умолчанию — v3. `AUDITMANAGER_EXTENDED_ANALYSIS_PLAN=v2` выбирает сохранённый параллельный план полного документа без нового критика/корректора; `AUDITMANAGER_EXTENDED_ANALYSIS=0` отключает расширение новых запусков. Эти переключатели не переписывают согласованные команды, журналы и результаты старых прогонов. Изменённый после согласия SHA требует новой оценки/согласия.

Параллельные коммиты владельца сохраняются при синхронизации dev: оформление, исправление двоичной загрузки ZIP, optional-schema Codex и HOTFIX-FULL-ANALYSIS-1030. Сохранены уже принятые v2 `max_blocks="all"` и прежние16. Свежий v3 также выбирает весь принятый объём, но его ограничение контекста и число наблюдений на окно могут оставить непроверенный остаток; это показывается как частичное покрытие. `origin/main` не публикуется; доставка на стенд не входила в это окно.

Все проверки нового кода отложены по D-290, включая синтаксис, сборку, worker/DB/recovery, стоимость, браузер/скачивание и качество модельных результатов. Результаты проверок предшествующего v2 не переносятся на v3. Откат — переключение свежего плана либо отдельный forward-revert; историю принятых запусков не переписывать. Точный SHA публикации и удалённый read-back фиксируются в локальной передаче интегратора после push.
