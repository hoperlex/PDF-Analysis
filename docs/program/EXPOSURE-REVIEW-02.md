### 3.1 Route groups and their authorization register

### 3.5 The upload path and the blob path

* **Types and limits.** `uploadDocument` accepts a portal bundle (a ZIP, decided by magic bytes, not by the label: `routers/documents.py:50-57`) or a bare PDF; at most 250 MiB (`ingest/envelope.py:153`), 1 to 500 pages (`:155-156`), source file name at most 255 characters (`:163`) and sanitised (`ingest/bundle_members.py:115`).
  The bundle reader is the repository's own (`ingest/bundle_archive.py`): at most 8 entries and a compression ratio of 100 (`:119-120`), member size bounded by `MAX_BYTES`, central-directory size bounded (`:463`). PNG crops are checked for signature, digest and size (at most 16 MiB; `executors/image_input.py:19-45`) and for geometry
  (`ingest/crop_geometry.py`: at most 4 000 000 pixels). The price-list upload parses `.xlsx`/CSV with member, part and column ceilings and **refuses a DOCTYPE or entity declaration before parsing** (`optimisation/parsing/xlsx_source.py:12-16`).
* **Parser exposure.** PDFium runs as a program of its own: `python -I -B pdf_reader.py`, the PDF as an inherited descriptor, a bare environment `{"PATH": os.defpath}`, `RLIMIT_AS`, `RLIMIT_CPU` and a zero core limit, a wall clock in the parent
  (`ingest/envelope.py:212-214,470-477`, `ingest/pdf_reader.py:64-68`). A hostile PDF can cost it time and address space, not the API's memory. What the boundary does **not** do is separate users or secrets: the child runs as the API's uid, in the API's container, and a same-uid process reads its parent's environment through
  `/proc/<ppid>/environ`. Measured with the same call shape on this host (`subprocess.run([sys.executable, "-I", "-c", ...], env={})` reading `/proc/<ppid>/environ`): the sentinel set in the parent's environment at start is readable by the child. The `api` container's environment holds `DATABASE_URL` (bootstrap superuser),
  the MinIO root keys and `AUDITMANAGER_API_TOKEN` (`compose.server.yml:203-224`). So the one thing standing between a PDFium memory-safety bug and those secrets is that bug not existing: `F-04`. (The provider key is not in the `api`; it is in the `worker`, which does not parse uploads.)
* **Blob access.** The bucket is private (`mc anonymous set none`, `infra/local/bucket-init.sh:75`), MinIO publishes no port, and the API streams bytes itself: "There is no redirect and no presigned link" (`routers/documents.py:9`; `storage/port.py:5`: the port exposes no delete, overwrite, presign or list). Streaming answers a fixed `application/pdf` /
  `image/png` (`routers/documents.py:50`, `routers/blocks.py:37`) behind `nosniff` (`nginx.conf:283`); the browser shows a document in its own PDF viewer through an `<object>` on a blob URL (`web/src/widgets/norm-document/ui/norm-document.tsx:142`, `web/src/features/open-evidence/model/use-evidence-document.ts:53`): no application-side PDF script engine (`pdfjs-dist` is not in `web/package-lock.json`).
  Identity of everything is a ULID-style id; a path or file name is never an identity.
* **Exports.** `exportRunXlsx` writes every string as an `inlineStr` ("Inline strings are text even when their first character is =, +, - or @", `exports/xlsx/writer.py:136-141`) and the optimisation CSV is formula-escaped (`optimisation/proposals/export.py:6`, `escape_formula`); **`exportRunCsv` is not**:
  `exports/serializer.py:76-89` (`_cell` returns `str(value)`) and `:97-118` write `finding_text`, `recommendation_text`, `evidence_quote` and `latest_comment` as they are. `evidence_quote` is a verbatim quotation from the client's document: `F-11`.
* The two upload locations and the slots: `E-5` and `F-10`.

## 6. What was checked and found sound

* The authorization seam is total over the contract (104 of 104 operations in exactly one register, none unregistered), deny-by-default for an operation named in no register, attached to every route including the documentation routes (`security.py:1137-1214`; section 3.1).
* Exactly three operations answer without a credential; a runner token and a user credential are separate principals that cannot be exchanged (`security.py:261-264`, `executors/runner.py:279-303`).
* Runner tokens: 256-bit, hashed, constant-time compared, scoped to one connection, one answer for every failure, images bound to the live claim and the task's own payload.
* Roles are read from the account row on every request and never from the credential; a revoked or archived account is refused at the next request; credentials live one hour (`security.py:519`).
* `issueToken` is throttled per address at the edge; the registration pair too; the runner paths in two zones; uploads authenticate before the body (`E-4`, `E-5`).
* `X-Forwarded-For` is read by no application code; `X-Real-IP` and `X-Forwarded-Proto` cannot be forged through either listener; open-redirect and cross-site POST guards exist in the BFF (`screen-registry.ts:447-452`, `web/src/app/bff/v1/[...path]/route.ts:600-606`).
* Port 80 has no route to the application (`acme-challenge.conf` has no `proxy_pass`); the ACME client is on a network shared only with the proxy and cannot reach the data tier (`D-229` item 3); its account key never reaches the proxy.
* Sealed connection keys: a database dump opens nothing, the `api` cannot open a key, an edited destination unbinds the key, a stolen administrator session cannot read a key.
* Model destinations are resolved once, classified and pinned; no redirect, no environment proxy; SSH uses a pinned host key; the probe sends no client data.
* The PDF reader is a separate, rlimited, bare-environment process; ZIP bundles, PNG crops and `.xlsx` price lists have hostile-input ceilings; the object store is private, unpublished and never presigned.
* The access journal accepts only allow-listed keys with value rules; no password, hash, token, cookie, name, e-mail or address can be written by it.
* The web tier calls no third-party origin, has telemetry off, uses no `dangerouslySetInnerHTML`, ships no `pdfjs-dist`, and shows a PDF in the browser's own viewer.
