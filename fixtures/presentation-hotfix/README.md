Первые четыре ZIP содержат исключительно PDF и предназначены для модулей сравнения. Два portal ZIP содержат PDF, blocks JSON и results MD (АР также HTML/audit); их загружают через обычный документ раздела, **не** через «Импорт ZIP» сравнения версий. IMAGE — область страницы в блоках портала: система вырежет из настоящего PDF изображение для исполнителя. Описание IMAGE в MD не является ответом модели.

## Перед показом

API, worker и web должны использовать один кандидат `dev` с API1.14.0; migration head остаётся `0043_stage_ai_generations`. Для сравнений включить `AUDITMANAGER_COMPARISON_MODULES=versions,stages`. Расширенный обзор новых обычных прогонов включён по умолчанию; `AUDITMANAGER_EXTENDED_ANALYSIS=0` отключает его только для новых оценок/согласий.

Для IMAGE нужен исполнитель с поддержкой PNG. HTTP-каналы передают изображения провайдеру; SSH требует обновлённый `tools/executor-runner/claude_answer.py` на самом исполнителе, публикация исходников в dev сама его не устанавливает. Оператор проверяет модель/цену, рабочую связь и установленный текущий нормативный корпус. При отсутствии корпуса нормативные ссылки остаются непроверенными. Экспериментальный V3 работает только с native text PDF и не заменяет графическое сравнение.

## Анализ: АР и ЭОМ

1. Открыть проект и нужный раздел. Загрузить `AR-native-image-portal.zip` в АР; отдельным документом `EOM-native-image-portal.zip` в раздел электроснабжения. Проверить предложенную классификацию и подтвердить правильный раздел. Не подтверждать АР для ЭОМ или наоборот.
2. Открыть подтверждённую версию. Проверить исполнителя/пресет; по умолчанию оставить обычные лимиты. Нажать **«Оценить стоимость»**.
3. Прочитать provider mode, объём и стоимость; принять конечный денежный потолок и поставить явное согласие. Затем **«Запустить прогон»**. Переключатель повышенных лимитов не заменяет согласие/потолок. После смены настроек или устаревшей оценки согласие требуется заново. Recorded mode означает тестовые ответы, не живую модель.
4. На странице прогона наблюдать реальный прогресс. Блок **«Предварительный обзор блоков»** показывает наблюдения, их источники и статус; открыть **«Источники наблюдения»**, при наличии — изображения исходных IMAGE областей. Отсутствующее изображение, непроверенные блоки или недоступные нормы не объявлять проверенными.
5. Для повторного прогона нужна свежая оценка/согласие. Не показывать пустой или частичный обзор как полный успешный анализ. Доступность живого исполнителя и установленного нормативного корпуса проверяет оператор, ZIP её не создаёт.

## Версии: VS1

1. «Сравнение версий» → выбрать проект → «Загрузить проект со всеми версиями». В отдельном блоке **«Импорт ZIP с версиями»** выбрать `VS1-five-versions.zip`, нажать **«Импортировать ZIP»**. Не добавлять одновременно отдельные PDF.
2. Дождаться предложения, проверить группировку и порядок v1→v2→v3→v4→v5; подтвердить состав/порядок и правильный раздел. Имена, номер «Изм.» и даты — подсказки, решение принимает оператор.
3. Выполнить разбор/сопоставление, открыть матрицу; при необходимости исправить связи вручную. Запустить сравнение соседних версий. AI-проверка пар и AI-описание — отдельные оценки и явные согласия, не автоматическое доказательство изменения.
4. Кнопка **«Полные спецификации (СО)»** находится между описаниями и отчётом. Если вход содержит СО — оценить нужный переход, подтвердить согласие, запустить; просмотреть охват/ограничения/позиции. Если СО нет — показать этот факт, не обещать результат СО. Это отдельный запуск, общая очередь его скрыто не оплачивает.
5. **«Обновить результат и сводку»**, скачать MD/PDF при наличии результата. **«Технический XLSX»** и **«HTML с изображениями (ZIP)»** читают сохранённые детерминированные свидетельства и не вызывают модель. HTML содержит обзорные исходные страницы, а не цветное наложение; наложение смотрят во viewer.

## Стадии: классика и отдельный V3

1. «Сравнение стадий» → вкладка **«1. Загрузка документации»**. Импортировать OLD как П, NEW как Р; подтвердить документы. Для правой стороны создать сборку из трёх реальных документов и назначить базовый участник по содержанию, не по выдуманному номеру.
2. Создать пару П→Р, открыть **«2. Сопоставление листов»**, проверить карту. Для классического показа можно использовать отдельную Р-сборку из graphic derivative; производная явно обозначена выше.
3. В управлении запуском **«Метод сравнения стадий»** по умолчанию классический. Полный запуск с ИИ требует оценки и согласия. Проверять реально завершённые шаги, исходные свидетельства и ограничения регистрации.
4. Для отдельного опыта выбрать **«V3 · эксперимент, только текст PDF»**. ИИ обязателен; пределы16страниц/80000знаков/400фрагментов. Это не графический V3 и не нормативная экспертиза. Оценка/согласие охватывают **один следующий** модельный вызов. После паузы нажимать **«Продолжить»**, получать свежую оценку и явно соглашаться для следующего вызова. Не обещать весь разбор за начальную оценку.
5. Наблюдать настоящие процедуры: Mapper, Miner, разбор непарных страниц, Dedupe, проверка параметров, карточки. Отсутствующий статус не означает завершение. Во вкладке **«3. Изменения проекта»** параметры показывают исходные значения и отдельную машинную сверку; PENDING/unknown — «Не проверено», CORRECTED не является решением инженера.
6. При реальном завершении эксперт может принять/отклонить карточки с причиной, затем открыть **«4. Отчёт»** и журнал/выгрузки. Подготовленные архивы не содержат этих результатов.

## Воспроизведение и границы проверки

Из корня репозитория: `.venv/bin/python fixtures/presentation-hotfix/build.py`. Генератор использует только существующие synthetic PDF, pinned repo font и portal-bundle writer; записи ZIP/PDF имеют фиксированные metadata. `SHA256SUMS` содержит хеши всех6архивов, `provenance.json` — исходные файлы/хеши, страницы и TEXT/IMAGE counts. EOM native text извлечён независимым fixture reader, а не подставлен вручную в PDF-факты.

Проверено локально: CRC/состав ZIP, PDF-only policy архивов сравнения, принятие обоих portal bundle fixture validator, наличие native TEXT и IMAGE областей, повторяемость байтов генератора. **Не выполнено:** загрузка браузером, реальный model call, качество выводов/поиск норм, deployment или весь показ. Любые оставшиеся живые проверки — только после dev, по решению интегратора и в общем бюджете до$10.
